# Production Visual · 图文视觉

> 一句话：先把文案压成一句判断，再决定这一页长什么样。

## 核心定位

- 适用：把已成形的文案 / 结论转成竖版图文卡片、封面套图、单张海报或信息图；也适用于只要 prompt 的场景。
- 只负责「文案 → 视觉」这一层：主判断、卡片节奏、版式、配色、构图、可控 prompt。
- 上游边界：内容结构与论点排序由 `harold-production-pack` 产出。本技能不新增、不合并、不重排论点；某段文案压不出一句判断时，退回上游，不替它编。
- 下游边界：PPT / 汇报页的页面类型与版式由 `harold-production-slides` 负责。本技能只管社媒竖版图文与单张视觉，不产出逐页 PPT 规格。
- 不负责：真实出图、跨平台发布、数据计算。出图交生图工具，发布交发布流程。

## 触发场景

- "把这段文案做成一组封面 / 图文卡"
- "照这张参考图的风格，给我重做一套"
- "给一条能直接投喂的生图 prompt，我要稳稳出图"
- "这组图看起来像 AI 模板，帮我定版式和配色"
- "这篇文章拆成一组卡片发给客户"

## 工作流

### Step 0 接料检查（缺项先问一个，其余写假设）

| 项 | 合格标准 | 缺失时 |
|---|---|---|
| 文案 | 有一段可读的原文或已列出的 3 条要点 | 只给主题时先要文案或要点；拿不到原文不得虚构论点，改出"配图位预留清单"（每张标明需承载的论点与建议文案长度），并注明"待文案补充后出图" |
| 主判断 | 能压成一句 6–14 字的主张 | 由本技能从文案中提炼，标"待确认" |
| 用图位置 | 封面 / 正文卡 / 单张海报 / 只要 prompt | 默认：封面 + 正文卡全套 |
| 比例与渠道 | 3:4 竖版 / 1:1 / 9:16，发布还是自用 | 默认 3:4 竖版 |
| 事实状态 | 是否含数字、日期、公司、版本 | 含则进入 Step 6 标注 |

**模式路由：先定交付模式，再决定跑哪几步。**

| 模式 | 判据 | 执行路径 | 裁剪 |
|---|---|---|---|
| 成套卡片（默认） | 2 张以上，有发布或分发意图 | 0 → 1 → 2 → 3 → 4 → 5 → 6 → 7 | 无 |
| 单张海报 / 封面 | 只要 1 张 | 0 → 1 → 3 → 4 → 5 → 6 → 7 | 跳过 Step 2，改成单页脚本：一句判断 + 一个支点 + 一个组件 |
| 只要 prompt | 用户明说"给我 prompt / 我自己出图" | 0 → 1（改写为视觉命题）→ 3 → 4 → 5 → 6 → 7 | 跳过 Step 2；Step 7 只写约束，不要求渲染 |

模式一旦确定就不中途换：先按卡片做完再问"能不能只要 prompt"，会多做一遍叙事。

### Step 1 压成一句主判断

一句话必须同时含"谁 / 变了什么 / 意味着什么"中的两项，其中"变了什么"必含。句中要有具体对象与可观察的后果，不能只有"更强、更智能、全新升级"这类形容词。
判据：这句话能被一条证据支持，或被一条反例推翻；两句都成立时选后果更具体的。

只要 prompt 时，把主判断改写成**视觉命题**：一句话说清读者看完画面该得到什么认知（如"这套流程被压成一步"），同样 6–14 字、可独立成立，写进 prompt 的叙事层，而不是标题层。

### Step 2 出卡片脚本（先叙事，后装饰）

张数按原文长度定，不套固定张数模板：单篇 3000 字以内 = 1 封面 + 2–4 张内文图；3000–6000 字 = 1 封面 + 4–6 张内文图；超过 6000 字先确认是否拆成多篇。
原文 ≤800 字或只有一条结论时，只出 1 张封面（最多加 1 张证据页），不为了凑套数硬拆；成组的下限是"还有第二个论点可讲"，不是张数。

| 职责 | 承担什么 | 张数不足时 |
|---|---|---|
| 01 封面 | 停留率：一句强判断 + 一个组件 | 始终保留 |
| 02 变化 / 机制 | 讲清"发生了什么" | 始终保留 |
| 03 证据 | 数据、案例、时间线，建立可信度 | 3 张时并入 02 |
| 04 判断 | 形成可传播观点 | 3–5 张时并入 05 |
| 05 收束 | 一句话收束，负责收藏与转发 | 始终保留 |

按张数取用：3 张 = 01 / 02（含证据）/ 05（含判断）；4 张 = 01 / 02 / 03 / 05；5 张 = 03 拆两张；6 张 = 02、03 各拆两张，04 并入 05；7 张再把 04 单列。每张只承载一个判断，文章段落不搬进图里。

### Step 3 选视觉方向（一套只用一族，中途不换色）

| 族 | 用在 | 形态 |
|---|---|---|
| A 终端发布页（默认） | 产品更新、工具、技术、商业复盘 | 深黑底 + 扫描线 + 超大中文标题 + 终端/时间线/数据卡 |
| B 博物馆图鉴 | 知识拆解、服饰器物、体系科普 | 纸感浅底 + 中心主视觉 + 引线标注 + 材质小样 |
| C 叙事海报 | 单张封面、观点、城市/品牌主题 | 一个强轮廓或一条强动线 + 大面积留白 + 克制排版 |

参数读 `references/visual-system.md`。

### Step 3.5 复刻参考图（有参考图时必做，先拆再画）

1. 拆解成"风格契约"：画布比例、网格与安全边距、三级字阶的像素关系、色值与各自占比、组件清单、留白节奏、质感来源（噪点 / 纸纹 / 反光）。
2. 列"不可复刻清单"：对方账号名、头像、水印、品牌标识、原文案、真实数据、可识别人物肖像。
3. 等比迁移：换算边距与字阶，不拉伸画面；组件结构与文案全部换掉，只保留版式关系。
4. 先出 1 页试样确认，再批量出其余页。

契约模板读 `references/visual-system.md` 的「复刻契约」。

### Step 4 落版式与配色

先定尺寸、安全边距、字阶、色比，再写 prompt。先写 prompt 再补版式，等于让模型替你决定层级。
单页单强调色；对比图例外：允许双色，但必须是同一色系的两个明度档（如 90% / 55%），不引入第二种色相。
语义色一组图内锁定，不跨页互换：绿 = 规模 / 总量，黄 = 增长 / 变化，粉 = 效率 / 成本；没有语义就别给颜色。
数据类组件统一执行：差异值必须有数值标签、单位或线型兜底，颜色只作辅助。
文字对比度按 WCAG AA 兜底：正文与小字 ≥4.5:1，大字（≥24px 常规或 ≥18.66px 粗体）≥3:1；对比度不够就换色，不改字号凑。
对比图除明度差外必须再加一种非颜色编码（文字标签 / 线型 / 填充纹理），不靠颜色单独区分。
字体只用可商用或系统字体；交付注明字体名与授权状态，不确定标"待确认"，不把未授权字体写进 prompt 让模型模仿。
安全边距要扣掉平台遮挡：小红书信息流底部 10–20% 会被标题栏与互动图标覆盖，结论条、数字、标题不得放入。强调色合计 ≤10%（主 4–7% + 辅助 1–3%），按像素占比量，不靠目测；超限先减组件，不加饱和度。

### Step 5 写 prompt：九层转换链

按「媒介 → 主体 → 构图 → 光线 → 材质 → 色彩 → 叙事 → 文字/版式 → 负面约束」逐层写。
抽象审美词后面必须跟可见证据词（"高级"后面要写"细噪声、哑光、边距一致"）。
中文文字优先用 HTML/CSS 渲染，生图只负责背景与装饰；必须让模型写字时，限定"简体中文、短句、少字、清晰可读"。
版式约束写进 prompt 本身，不留在方案里：画布比例、边距占比、字阶比（标题 : 正文 : 标签 ≈ 4 : 2 : 1）、单强调色及占比上限、对比度要求。
模型偏离时一次只改一层，顺序：构图 → 光线 → 材质 → 风格词；同时改两层无法归因，只会越改越糊。
结构模板读 `references/prompt-patterns.md`，结构参考读 `references/prompt-cases.md`。

### Step 6 事实与文字保护

- 涉及公司、产品、融资、收入、增长、日期、版本、市场数据，不确定就标"待核验"。
- 示意数字一律标"示例，非真实数据"，不用具体数字冒充结论。
- prompt 里可以写 `mock data / illustrative labels`，正式发布稿必须换成已核验信息。
- 用户要求"真实数据图表"时，不编数：要口径与来源，或改用可核对的数据工具输出。
- 真实数据不交给生图模型：数字会失真且无法核对。用 HTML/CSS 或表格工具渲染后截图，prompt 里只放占位框与 `mock data`。

### Step 7 质检（逐项给结论，并写明失败时改什么）

把成图缩到宽 360px（约信息流缩略尺寸），只看 2 秒，再逐项判：

| 项 | 通过判据 | 不通过时按顺序改，一次只改一项 |
|---|---|---|
| 2 秒测试 | 能复述主标题，且不会读成别的意思 | 删字 → 拆行 → 提对比 → 删次要组件 |
| 单一视觉中心 | 视线第一落点唯一；两个以上元素争抢即不通过 | 缩次要元素字号 / 去色 / 移出中心 |
| 强调色占比 | 导出后按像素统计或组件面积核算，≤10%；目测不算 | 先减组件，再降饱和度，不加装饰补 |

一组图另查结构多样性：至少 3 种页面结构，不是同一模板换字。
只要 prompt 时不做渲染核验：把三项写成 prompt 内的版式约束（层级、单一中心、强调色占比上限、对比度），并在交付里注明"以约束代替渲染核验"。

## 文案 → 视觉的转换链（本技能的核心）

| 文案里的东西 | 转换动作 | 落到哪一层 |
|---|---|---|
| 一句结论 | 压成 6–14 字标题，关键词单独上色 | 版式 / 文字 |
| 3 条支撑证据 | 选一个主组件承载（终端窗口 / 时间线 / 三联卡） | 主体 / 构图 |
| 关键数字 | 做成数字卡：大数字 + 单位 + 口径小字 | 文字约束 |
| 立场与情绪 | 提炼一个强视觉支点（一条线 / 一个轮廓 / 一个光源） | 视觉支点 |
| 行业语境 | 转成材质与光的证据（噪点、纸纹、屏幕反光） | 材质 / 光线 |
| 用户禁区 | 反向写成负面约束 | 负面约束 |

同一条链路可用于单张海报：结论 → 标题 → 强支点 → 版式 → prompt。

## 输出格式

卡片方案（默认）：

```text
# 图文方案：<主题>

## 视觉方向
一句话风格 + 一个记忆点

## 假设与待确认
已补的默认项（比例 / 张数 / 渠道）+ 待用户确认的主判断

## 卡片脚本
| 页 | 目的 | 标题（6–14 字） | 画面结构 | 主组件 | 强调色 |

## 版式与配色
尺寸 / 安全边距 / 字阶 / 主色与强调色及占比 / 组件清单

## 逐页 Prompt
### 01 封面
<可直接复制的一段>

## 数据与事实标注
真实 / 待核验 / 示例，非真实数据

## 质检记录
2 秒测试 / 单一视觉中心 / 结构多样性 / 强调色占比 / 文字对比度
```

复刻参考图时，另加一节：

```text
## 风格契约与不可复刻清单
契约：比例 / 网格与边距 / 字阶 / 色值与占比 / 组件 / 留白 / 质感
不可复刻：账号、头像、水印、品牌标识、原文案、真实数据、可识别人物肖像
迁移说明：等比换算边距与字阶，不拉伸画面；先给 1 页试样
```

只要 prompt 时：

```text
## 结论
推荐哪版、为什么

## 视觉命题
一句话：画面要让读者看到什么（6–14 字）

## Prompt 1｜稳妥版
## Prompt 2｜传播版
## Prompt 3｜高概念版

## 参数
比例 / 边距占比 / 字阶比 / 单强调色及占比上限 / 对比度 / 风格关键词 / 负面约束
```

用户明确只要 1 条，就只给 1 条，不硬凑三版。

## 验收标准

**阻塞项：任一为 0，不得交付，不看计分项。**

- [ ] B1 不编造：数字标注真实 / 待核验 / 示例，无编造；没有来源就不按真实数据排版
- [ ] B2 不越界：不改内容结构，不混入 PPT 版式规格；无原文时不虚构主判断，改出配图位预留清单
- [ ] B3 主判断成立：成组卡片时，一句话且可脱离原文独立成立；只要 prompt 时，以"视觉命题"（画面要让读者看到什么）替代，同样须一句话、可独立成立

**计分项：**

- [ ] 1 卡片脚本每页一个判断，张数按字数口径有依据而非套模板；只要 prompt 时本项 N/A
- [ ] 2 版式参数具体：尺寸、边距、三级字阶、色比、文字对比度（正文 ≥4.5:1、大字 ≥3:1）；结构图 / 对比图参数齐备（对比图双色须同色系两档明度，并有文字标签 / 线型 / 纹理等非颜色编码）
- [ ] 3 prompt 覆盖九层：媒介、主体、构图、光线、材质、色彩、叙事、文字/版式、负面约束
- [ ] 4 中文可读性有方案（短大字，或改走 HTML/CSS）
- [ ] 5 一组图至少 3 种页面结构，非同一模板复制；只要 prompt 或无成组交付时本项 N/A
- [ ] 6 质检三项逐项给结论：缩到信息流缩略尺寸（约屏宽 1/3）2 秒内能读出主标题、每页一个视觉中心、荧光色像素占比不超过画面 10%；只要 prompt 时以 prompt 内的版式约束代替渲染核验
- [ ] 7 复刻参考图时只复刻版式契约（网格 / 字阶 / 色比 / 组件），不复制对方账号、水印、品牌标识与原文案；非复刻场景记 N/A，不计入分母

判定：阻塞任一为 0 = 重做；阻塞全过 + 计分 ≥⌈0.8×N⌉ = 可交付；计分 ≤阈值-1 = 重写。N 与阈值按场景换算（标 N/A 的项不计入分母）：成套卡片 7/6；成套卡片且非复刻 6/5；只要 prompt 5/4；只要 prompt 且非复刻 4/4（N/阈值）。N/A 仅限材料本身不具备该情形，漏做不算 N/A；用户豁免某项时仍计入分母，自检记为未做。

## Gotchas

1. **只复刻表面**
   高级感来自信息层级、留白、组件秩序和文字比例，不是黑底绿字。先问"这一页的主次是什么"，再谈颜色。

2. **满屏霓虹与装饰**
   发光只在边框周围，不做全图泛光；不加随机 3D 图标、机器人、科技城市背景。荧光色一超 10% 就廉价。

3. **让生图模型写长中文**
   中文一长就错字、断行、糊字。标题限定 6–14 字，正文交给 HTML/CSS。

4. **每张都做成封面**
   正文页要让信息系统说话。通篇大标题 + 大留白，读者拿不到信息，只会划走。

5. **只堆风格词**
   "高级、电影感、科技感"不构成指令。每条审美词后面补一个可见证据：噪点、反光、行距、材质。

6. **编数据凑版面**
   三个漂亮数字比没有数字更危险。没有来源就写"示例，非真实数据"，或改成交付占位框。

7. **参考图照抄**
   复刻的是版式契约（网格、字阶、色比、组件），不是对方的账号、水印、品牌标识与原文案。

8. **prompt 自相矛盾**
   "极简"同时"细节堆满"、"暗黑"同时"高饱和糖果色"，模型只会给你四不像。一次只留一对主次关系。

9. **借风格踩到人和署名**
   风格本身通常不受版权保护，但具体表达、真人肖像与"以某位在世艺术家之名"的暗示背书仍有风险。prompt 里不写在世艺术家姓名，不用可辨识真人形象；需要真人出镜时先确认肖像授权。

10. **把模式搞混**
    用户只要一条 prompt，却先给一套卡片脚本，再问要不要转成 prompt。模式在 Step 0 定一次，之后只跑对应路径。
