# Knowledge Cards · 知识卡片流

> 一句话：一张好卡片 = 一个概念讲透 + 一句人话类比 + 一个常见误区 + 一串关联线索。

## 核心定位

- 适用：名词释义、行业黑话、产品概念、人物拆解、知识点梳理；一次 20–40 张批量产出。
- 产物两个：`terms.json`（统一 Schema）+ 单文件 HTML 卡片流（滚轮翻页、目录、分类筛选、复制本条）。
- 不适用：长文写作（用 `harold-production-copy`）、PPT 版式（用 `harold-production-slides`）、需要引官方原文的法律与财会条文（去查原文）。
- 边界：卡片流用于快速扫读与转发，不承诺记忆效果；要让读者记住，需另配自测与间隔复习，本技能不做。
- 渲染引擎领域无关：换主题只换一份 JSON，不改代码。

## 触发场景

- "做一个 XX 的卡片"
- "把大模型常见概念做成可滑动的卡片"
- "做 20 张私域流量术语卡"
- "整理一份行业黑话，每张卡讲清楚"
- "做一套人物拆解卡片"

## 工作流

### Step 0 定三件事

1. **主题边界**：一个主题，一次一副牌；跨领域就分两副。
2. **张数与形态**：默认 20–40 张 `swipeDeck`（网页卡片流）；要边看边追问才用对话逐条出。
3. **分类体系**：写出 `categories` 映射（key → 中文标签）；人物主题用 Step 2 的五段式，映射必须写进 JSON。

缺哪项就在方案里标"假设"，一次只问一个。

### Step 1 出词

**用户已给词表**：直接用，Step 2 开始。

**需要现出词**：维护一份 6 列词库，用游标脚本按优先级出词（命令在技能目录下执行；换目录请用绝对路径，或省略 `--bank`，脚本默认指向本技能词库）：

```bash
# 预览下一批（不写状态）
python3 scripts/next_term.py --peek --count 10 --prefix fin

# 生成完成后提交，写回游标
python3 scripts/next_term.py --commit --terms terms.json
```

- 词库列格式固定：`| 名词 | 英文 | 分类 | 优先级 | 别名 | 风险标签 |`，优先级 1 高频 / 2 常用 / 3 长尾。
- 分类从词库动态识别，不用预先声明；`-` 表示无译名 / 无别名。
- `termId` 由脚本生成：`3 字母前缀 + 4 位数字`（`fin-0007`），前缀按主题定。
- 游标存在本机 `~/glossary-deck/state.json`，跨会话去重；换词库用 `--bank`，重置用 `--reset`。

### Step 2 写卡

每张卡一份 JSON，13 个必填字段 + 1 个可选字段 `aliases`（字段名保持英文 camelCase，内容简体中文）：

```json
{
  "termId": "exm-0001",
  "termZh": "完播率",
  "termEn": "Completion Rate",
  "category": "metric",
  "definition": "看完视频的人数占开始播放人数的比例，是衡量内容留人能力的核心指标。",
  "plainAnalogy": "像电影院里坐到最后的人数，跟买了票进场的总人数之比。",
  "whyItMatters": "平台用它判断内容值不值得继续给流量，低完播的视频几乎拿不到推荐。",
  "misuse": "很多人把完播率低直接当成内容差，其实开头三秒没钩住人也会低，问题可能只在开头。",
  "relatedTerms": ["互动率", "平均播放时长", "钩子"],
  "metricHint": "",
  "riskFlag": "none",
  "sourceType": "industryConsensus",
  "confidence": 0.9
}
```

写法约束：

| 字段 | 规则 |
|---|---|
| `termId` | `3 字母前缀-4 位数字`，同批递增；由 `next_term.py` 生成或手工对齐 |
| `termZh` | 2–20 字，是一个名词或一句短语，不是完整句子 |
| `termEn` | 英文对照；无通行译法留空 |
| `category` | 必须落在 `categories` 映射内，不得出现映射外的 key |
| `definition` | 30–160 字，超了重写不截断；首句给"属 + 种差"（它属于哪一类、与同类差在哪）；不得循环定义（"私域就是私域流量"），不得用本副牌里还没解释的术语解释它 |
| `plainAnalogy` | 生活类比，不得引入新黑话 |
| `whyItMatters` | 1–2 句，写"不知道会付什么代价"，不重复定义 |
| `misuse` | **信息增量最高的一栏**，必须写具体的人和具体的错法，"谁、在什么场景下、付出什么代价"至少写到两项，不能同义改写定义 |
| `relatedTerms` | ≤5 个，串成知识网 |
| `aliases` | 可选，同义写法数组；参与去重并在卡面显示为灰标签，不得与 `termZh` 重复 |
| `metricHint` | 格式固定为"数字 + 口径 + 来源 + 时点"（例：`30%＋＝长视频口径，平台后台 2026-06 行业均值`）；四项凑不齐就留空，不写"约""左右" |
| `riskFlag` | 普通内容 `none`；涉及合规填对应标签，标签名与提示语见 `scripts/render_deck.py` 的 `RISK_LABEL` / `RISK_TEXT` |
| `sourceType` | `officialDoc` / `industryConsensus` / `inferred` 三选一，判据见下表 |
| `confidence` | 0–1，按锚点打分：≥0.85 官方原文或多源一致；0.6–0.85 业内通行但有分歧；<0.6 无统一口径（卡面自动加提示） |

`sourceType` 判据：

| 取值 | 什么时候用 | 硬要求 |
|---|---|---|
| `officialDoc` | 有官方文件、平台规则或标准原文 | 卡面写得出机构 + 文件/页面名 + 时点，并给得出可复核位置（链接或章节号） |
| `industryConsensus` | 业内通行但无单一权威原文 | `definition` 用"业内通行口径"表述，且至少两个独立来源方向一致（证据留在待核清单） |
| `inferred` | 自己的归纳或类推 | 全卡不得出现任何具体数字、比例、金额与出处 |

**一张卡只讲一个概念**：`definition` 只解释这一个名词，不并列第二个概念；需要并列时拆成两张卡，用 `relatedTerms` 串起来。

**人物主题用五段式**（33–42 张一副，五段都要有；`fall` 不得并进 `life`，否则整副牌变成吹捧）：

| 分类 key | 中文标签 | 张数 | 装什么 |
|---|---|---|---|
| `life` | 生平轨迹 | 6–8 | 只留决定性节点：出身 / 转折 / 终局 |
| `works` | 伟大作品 | 8–11 | 一件作品一张，写清"当时行业默认是什么、他改了什么" |
| `mind` | 核心思考 | 7–9 | 方法论与信念，每条配一句原话 |
| `fall` | 起落沉浮 | 5–6 | **必须写失败与暗面**，否则整副牌变成吹捧 |
| `lesson` | 创业启示 | 7–8 | 可迁移结论，落到读者自己的业务 |

人物主题必须在 `terms.json` 顶层显式给映射，否则渲染会因 `life`/`works` 缺中文标签直接退出：

```json
{"categories": {"life": "生平轨迹", "works": "伟大作品", "mind": "核心思考", "fall": "起落沉浮", "lesson": "创业启示"}}
```

`mind` 每条要配一句当事人原话；找不到可核实原话就写"原话未核实"，不得改写或自拟。

### Step 3 自检

逐项过：

1. **字数与结构**：`definition` 30–160 字、`termZh` 2–20 字且是名词；`misuse` 写到"谁 / 场景 / 代价"至少两项。
2. **互引检查**：逐卡通读，`definition` 里出现的其他名词，要么是常识，要么本副牌内有解释并进了 `relatedTerms`；否则改写或补卡。
3. **可信度**：`confidence<0.6` 的卡有"业内无统一口径"提示；`sourceType=inferred` 的卡没有任何具体数字与出处；`officialDoc` 的卡写得出可复核位置。
4. **去重**：`termZh` 与别名不重复，`termId` 同前缀连续递增。
5. **风险**：`riskFlag≠none` 的卡有对应提示语，且提示语不是默认兜底文案。
6. **待核清单**：把低可信、单源、原话未核实、数字缺口径的卡单列出来交给用户，不藏在正文里。

### Step 4 渲染

```bash
python3 scripts/render_deck.py \
  --input terms.json \
  --output deck.html \
  --title "金融术语 · 30 张卡片" \
  --kicker "FINANCE GLOSSARY" \
  --subtitle "基础概念 · 流量玩法 · 合规风险"
```

- 顶层可以是数组，也可以是 `{ "categories": {...}, "risks": {...}, "terms": [...] }`；`categories` 显式给了就整体替换默认映射，`risks` 显式给了按 key 增补或覆盖，不会把内建标签顶掉。
- 缺中文标签的 category 或 riskFlag 会让脚本直接退出——这是有意的，避免卡片上出现裸英文 key。
- `--layout split`（默认，左右双栏一屏看全）/ `stack`（单栏，适合窄屏或打印）。
- `--kicker` 不传时按标题关键字推断；推断不中就用通用 `INDUSTRY GLOSSARY`，直接传更稳。
- 交互已内建：滚轮 / 触控板一次手势翻一条（430ms 节流抵消惯性）、方向键与空格、目录面板、分类筛选、复制本条、自动播放。

### Step 5 交付

- 交付 `deck.html` 与 `terms.json`，说明双击即开、可离线转发。
- Step 3 的待核清单随交付一并给出，写清哪几张卡在引用前需要用户复核。
- 用了 `next_term.py` 的，记得 `--commit` 写回游标，否则下次重复出同样的词。
- 批量对外发布前，检查人名、客户名与内部数据是否需要脱敏。

## 输出格式

```text
# 卡片流：<主题> · <张数>

## 1. 主题与分类
- 分类体系：<key → 中文标签>
- 张数：<n>｜形态：网页卡片流 / 对话逐条

## 2. 词条清单
| termId | 标题 | 分类 | sourceType | confidence | riskFlag |

## 3. 交付物
- terms.json（<n> 条）
- deck.html（<尺寸>，零依赖）

## 4. 自检结果
- 字数与结构 / 互引检查 / 可信度 / 去重 / 风险：逐项通过或列出待修

## 5. 待核清单
- <termId>：<待核原因（单源 / 原话未核实 / 数字缺口径 / 口径分歧）>
```

## 验收标准

**阻塞项：任一为 0，不得交付。**

- [ ] B1 卡片写法合规：`definition` 30–160 字且不循环定义、不引用本套牌未解释的术语，`termZh` 2–20 字且是名词不是句子，`misuse` 非空且写了具体的错法
- [ ] B2 不编造：`sourceType=officialDoc` 的卡片写得出可复核出处；`sourceType=inferred` 的卡片没有具体数据与出处；`confidence<0.6` 的卡片有"业内无统一口径"提示；`riskFlag≠none` 的卡片有风险提示
- [ ] B3 产物可离线：HTML 为单文件零外部依赖，双击可开，翻页、目录、筛选、复制四个交互都可用，键盘可达且焦点可见，尊重 `prefers-reduced-motion`

**计分项：**

- [ ] 1 分类体系显式声明，渲染后卡片上没有裸英文 key
- [ ] 2 同批去重：`termZh` 与别名不重复，`termId` 为 `前缀-4位` 且递增
- [ ] 3 人物卡用五段式，且 `fall` 段写了失败与争议（非人物主题标 N/A）
- [ ] 4 `misuse` 写了"谁、在什么场景下、付出什么代价"三项中的至少两项，不是把定义换个说法
- [ ] 5 `plainAnalogy` 的类比取自卡片主题之外的日常场景，且除 `termZh` 本身外不出现本套牌里的其他术语
- [ ] 6 用了游标脚本的场景已执行 `--commit`（未使用标 N/A）

判定：阻塞任一为 0 = 重做；阻塞全过 + 计分 ≥⌈0.8×N⌉ = 可交付；计分 ≤阈值-1 = 重写。N = 6，阈值 = ⌈0.8×6⌉ = 5；非人物主题第 3 项 N/A、未使用游标脚本第 6 项 N/A，单项 N/A → N = 5、阈值 ⌈0.8×5⌉ = 4，两项同时 N/A → N = 4、阈值 ⌈0.8×4⌉ = 4。N/A 仅限材料本身不具备该情形（非人物主题无 fall 段可查、未用游标脚本无 commit 可查），漏做不算 N/A；用户豁免某项时仍计入分母，自检记为未做。

## Gotchas

1. **定义超长就截断**
   截断会把话说完的半句留在卡片上。超过 160 字重写，不截断。

2. **人物卡写成吹捧**
   `fall` 段不写失败与争议，整副牌就立不住，读者也会觉得假。

3. **编造量化数字**
   `metricHint` 没有确切来源就留空。空着比编一个"约 30%"更可信。

4. **标题写成句子**
   "乔布斯为什么不写代码"是文章标题，不是卡片标题。卡片标题要能被检索、能被串进知识网。

5. **窄屏被双栏挤爆**
   900px 以下脚本自动切单栏，不要手改断点；要永久单栏用 `--layout stack`。

6. **复制按钮在 file:// 下失灵**
   脚本已用 `execCommand` 兜底非安全上下文，别"顺手优化"成只用 `navigator.clipboard`。

7. **词库越堆越乱**
   别名参与去重但不参与展示；同一概念只留一行，别名写在同一行的第 5 列。

8. **用 div 冒充按钮**
   可点元素若是 `div`/`span` + onclick，键盘 Tab 永远到不了，屏幕阅读器也读不出角色。模板里目录、筛选、复制、自动播放一律用 `<button>`，并保留 `:focus-visible` 描边。

9. **短屏把风险提示裁掉**
   桌面 `body` 不滚动，卡片超出一屏就被裁，最先消失的往往是底部的关联词与风险提示。卡片已用 `max-height + overflow-y` 内滚；wheel 处理里必须先滚完卡片内容再翻页，不要改回无条件翻页。

10. **风险标签缺提示语**
    新增风险标签必须同时补 `RISK_LABEL` 标签名与 `RISK_TEXT` 提示语。只补标签名会被渲染器拒绝；以前会静默回落到默认文案，把"版权与假货"写成"资质或宣传合规"，比报错更糟。

11. **全速动画无视系统设置**
    翻页位移与自动播放都是动效。`prefers-reduced-motion: reduce` 下必须直接切卡、不走过渡，别把 `transition` 当纯装饰。

12. **人物主题漏 categories**
    五段式只写在文档里、没写进 `terms.json` 的 `categories`，渲染器会因 `life`/`works` 缺中文标签直接退出。五段映射必须显式给。
