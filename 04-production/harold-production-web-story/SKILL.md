# Production Line · 网页故事

> 一句话：把一个主题做成一页能看懂、能打开、能验收的网页。

## 核心定位

- 产物形态：单页长滚动——一个 `index.html`，hero + 锚点导航 + 5–9 个章节 + 页脚。
- 适用：研究观察站、指南 / 榜单、项目介绍、课程专题页、活动落地页。
- 不适用：PPT / slides（用 `harold-production-slides`）、多页站点、需要后端 / 登录 / 支付的应用、海报平面设计（用 `harold-production-visual`）。

## 触发场景

- "把这个选题做成网页"
- "把研究结果做成一个网站"
- "做个观察站 / 指南页 / 落地页"
- "这个项目介绍要一个网页，手机也要能看"

## 工作流

### Step 0 接题（三件事）

开工前锁定：

1. 给谁看（具体人群与处境，不写"所有人"）；
2. 必须出现的事实（数据、时间、结论；数据要能标来源）；
3. 看完想要什么行动（转发 / 报名 / 关注 / 自行验证）。

能从上下文确认的不反问；缺失项写成假设并标注"假设，待确认"，不因缺一项停住，也不编事实。

"好看"不构成验收标准：转成可检查项——视口无横向溢出、正文对比度、可点元素尺寸、首屏信息完整、分享预览完整。

### Step 1 拆叙事

读 `references/narrative-patterns.md`，按选题类型选骨架：

| 骨架 | 适用 |
|---|---|
| A 研究观察站 | 持续追踪一个行业或主题 |
| B 指南 / 榜单 | 可比较的对象集合，给选择建议 |
| C 项目介绍 | 一个产品、项目或作品 |
| D 课件专题 | 一节课或一个专题，供回看 |

拆成 5–9 章，每章一个论点，章节标题写论点不写类目名；超过 9 章先合并。

阅读预算：全文 2–3 分钟读完，每章正文 40–120 字；超了说明这章该拆或该删，不是该加排版技巧。

### Step 2 大纲闸门

先交大纲：hero 一句话 + 各章标题与核心论点 + 事实清单（每条标来源口径：官方 / 财报 / 社区 / 估算）。有争议的结论并列正反信号，不只留一边。
用户确认后再进视觉与编码；未确认不写页面。

### Step 3 套模板做视觉

1. 把 `assets/template/` 复制到项目目录，改副本，不改技能内模板。
2. 视觉决策对照 `references/design-system.md`。
3. 移动优先：先写 375px，桌面用 `min-width` 做加法；动效用 CSS transition，尊重 `prefers-reduced-motion`。
4. 模板是最小骨架（hero + 3 个正文 + 行动 = 5 章）；按 Step 2 的大纲只增不减，合计保持在 5–9 章，导航项与章节 id 一一对应。
5. 页面头部写全 `<html lang="zh-CN">`、`<title>`、`og:title` / `og:description` / `og:image`（绝对 URL，1200×630）；信息图写 `alt`，装饰图 `alt=""`。
6. hero 图用 WebP / AVIF，宽度按容器 2 倍准备、单张 ≤300KB，写 `width` / `height` 防位移；首屏 LCP 目标 ≤2.5s、CLS ≤0.1。
7. 写 CSS 前过一遍 `references/pitfalls.md`。
8. hero 3 秒测试：遮住正文只看首屏，3 秒内能否说出"这是什么 + 为什么现在值得看"。说不出就改标题、删形容词，不加动画补救。

内容规则：数字必须带来源与时点，无来源就写事实不写数字；不用 emoji 当图标；不写"赋能 / 一站式 / 全方位"。

### Step 4 双端验收

先跑内容校验，再跑双端 QA（需要 Node.js，项目内 `npm i playwright`）：

```bash
node <skill>/scripts/validate-content.mjs --root .
node <skill>/scripts/web-qa.mjs --root .
```

通过标准：桌面 1440、平板 768、手机 430 / 390 / 375 / 320 无横向溢出；控制台零错误；图片全部加载且信息图有 `alt`、装饰图 `alt=""`；正文对比度 ≥4.5:1；独立可点元素触控高度 ≥44px（内部标准，严于 WCAG 2.5.8 的 24×24 AA；图标按钮 ≥44×44px；正文句内链接按 2.5.8 Inline 例外豁免，脚本单独计数）；键盘 Tab 焦点可见；系统开启"减少动效"后无滚动进入动画与平滑滚动；首屏 LCP ≤2.5s、CLS ≤0.1、INP ≤200ms（本地 Lighthouse 移动端，脚本数值仅作参考；无法测则写明）；head 含 `title` / `og:title` / `og:description` / `og:image`（绝对 URL，1200×630）；截图存入项目 `EVIDENCE/`。
有特定探针时在项目根写 `qa.expect.json`（选择器 → 预期数量），脚本自动比对。缺 Playwright 或无法装依赖时，改为手工核对同一组视口，并在交付中写明"未跑脚本，手工核对"，不假装已跑。

### Step 5 部署路由

先干跑确认路线：

```bash
node <skill>/scripts/deploy-plan.mjs --root .
```

| 优先级 | 条件 | 动作 |
|---|---|---|
| a | 环境有内生网页托管 | 用平台发布能力，发布后读回验证 |
| b | 能生成公网链接 | 生成 URL 并验证；说明临时链接有效期 |
| c | 项目配置了自有域名 / 云存储 | 按 `references/deployment.md` 走对象存储 + CDN，或 Vercel |
| d | 都没有 | 交付本地 `index.html` 并打开预览，附上线指引 |

凭证只读本机已有配置，不写进项目文件。公网部署后必须读回：状态码 200、字节数与本地一致、页面内独有文本能 grep 到。

## 验收标准

**阻塞项：任一为 0，不得交付。**

- [ ] B1 接题三件事已锁定：受众 / 必须出现的事实 / 目标行动；缺失项写成假设并标注"待确认"，未编事实
- [ ] B2 大纲先确认后编码：5–9 章、每章一句论点、含 hero 与结尾行动，用户确认前没有产出页面
- [ ] B3 验收与部署有记录：validate-content 已跑；web-qa 已跑或按 Step 4 手工核对六视口（含 320px），控制台零错误；图片 alt、键盘焦点、减少动效、分享卡片四项各有结论；交付含视口结果与部署方式；公网部署有读回验证

**计分项：**

- [ ] 1 视觉符合设计系统：移动优先、主色 1 个、间距为 8 的倍数、正文对比度 ≥4.5:1、独立可点元素触控高度 ≥44px（内部标准，严于 WCAG 2.5.8 的 24×24 AA；句内链接按 2.5.8 Inline 例外豁免）
- [ ] 2 内容无占位与空话：无 TODO / 占位 / Lorem ipsum，无"赋能 / 一站式 / 全方位"，数据带来源口径与时点
- [ ] 3 双端无溢出：320–1440 六个视口均无横向滚动；图片不塌陷、不变形
- [ ] 4 部署按四级降级选择，公网链接说明有效期，凭证未写入任何项目文件；对外分享时 title / og:title / og:description / og:image（绝对 URL）齐备
- [ ] 5 首屏信息完整：hero 一句话说清"这是什么 + 为什么值得看"，手机一屏能看完、3 秒内能判断值不值得继续读；首屏 LCP ≤2.5s、CLS ≤0.1、INP ≤200ms（本地 Lighthouse 移动端，无法测则写明）

判定：阻塞任一为 0 = 重做；阻塞全过 + 计分 ≥⌈0.8×N⌉ = 可交付；计分 ≤阈值-1 = 重写。N 与阈值按场景换算（标 N/A 的项不计入分母）：单页网页 N=5、阈值 4。N/A 仅限材料本身不具备该情形，漏做不算 N/A；用户豁免某项时仍计入分母，自检记为未做。

## Gotchas

1. **直接改技能里的模板**
   模板是起点不是产物。先复制到项目目录再改，否则下一个项目带着上一个项目的文案。

2. **只验 375，不验 320**
   横向溢出和大字挤压几乎只在 320px 暴露。320 不过就是不过。

3. **首屏裸写 `100svh`**
   会在大屏上撑出一大块假留白。用 `min-height:min(88svh, 860px)` 这类带上限的写法。

4. **截图截到半成品**
   页面渲染完设 `document.documentElement.dataset.ready='true'`，验收脚本等这个标记；首屏图用 `loading="eager"`。

5. **部署看到"成功"就当上线**
   构建成功不等于可访问。必须 curl 读回：状态码、字节数、独有文本三项都过。

6. **数据没来源就编一个**
   宁可写事实不写数字。编造的数字一旦被读者核到，整页可信度归零。

7. **粘性导航把章节标题压在下面**
   有 sticky / fixed 导航时，锚点跳转必须配 `scroll-padding-top` 或章节 `scroll-margin-top`，值不小于导航高度；否则每次点导航，h2 都被挡住一截。

8. **hero 图直接从设计稿导出原图**
   一张 3MB 的 PNG 会把首屏拖到 4s 以上。导出 WebP / AVIF，按容器 2 倍宽压到 ≤300KB，写死 `width` / `height` 防位移。

9. **页面做完了，发出去是裸链接**
   只写 `<title>` 不够。`og:title` / `og:description` / `og:image`（绝对 URL、1200×630）缺一项，朋友圈和聊天窗口就没有预览卡。

10. **图片没有 alt，或装饰图也写了描述**
    信息图用一句 `alt` 说清它传达的结论；纯装饰图写 `alt=""` 让屏幕阅读器跳过，不要省略属性，也不要写"图片"。键盘 Tab 时焦点框被全局 `outline: none` 抹掉，同样算不过。

11. **为了"高级感"劫持滚动**
    拦截 wheel / touch 控制滚动速度、做滚动锁定、把叙事塞进 canvas，会让读屏和键盘用户拿不到内容。滚动叙事只做"进入视口触发淡入"，不接管原生滚动；每一步的含义必须落在真实 DOM 文本里。
