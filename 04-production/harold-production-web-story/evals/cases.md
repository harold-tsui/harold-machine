# 验收用例：网页故事

## Case 1 · 一句话就要一个网页，其余信息全无

**输入**："把我上周写的'县域咖啡'那篇做成网页，好看点，能发朋友圈。"

**期望特征**
- 先补或假设接题三件事：给谁看、必须出现的事实、看完的行动；缺失项标"假设，待确认"，不装作已确认。
- 不直接生成页面，先给 hero 一句话与 5–9 章大纲，等确认。
- 章节标题是论点，不是"背景介绍 / 详细分析"这类类目名。
- 明确指出"好看"不是验收标准，给出可检查项（视口无溢出、对比度、触控尺寸）。
- 大纲带阅读预算：全文 2–3 分钟读完、每章正文 40–120 字，超出的章合并或删。
- 事实清单里标出哪些数字需要原文提供来源。
- 交付前补 head 分享卡片（title / og:title / og:description / og:image 绝对 URL），否则"发朋友圈"是裸链接。

**常见失败**：直接输出一整页代码；默认 375px 就够了；用渐变和 emoji 充当"好看"；页面能看，但发出去没有预览卡。

## Case 2 · 研究结论要做成行业观察站

**输入**："这份报告有 6 个发现，帮我做成一个行业观察站，能长期更新。"

**期望特征**
- 选择骨架 A（研究观察站），按"大图景 → 时间线 → 玩家墙 → 争议 → 结论"组织，不按报告目录照搬。
- 6 个发现归并进 5–9 章，每章一个论点；有争议的结论并列正反信号；每章正文 40–120 字，写不下说明该拆章而不是堆长文。
- 每个数据标来源口径与时点；无来源的写为事实陈述，不补数字。
- 复制模板到项目目录再改，交付 `outputs/YYYY-MM-DD_<主题>/index.html`。
- 验收覆盖 320 / 375 / 390 / 430 / 768 / 1440，截图存 `EVIDENCE/`。

**常见失败**：报告段落直接搬成章节；结论只留正面观点；全页只有 375px 截图。

## Case 3 · 做完要上线给外部看

**输入**："页面好了，帮我发出去，客户要能打开。"

**期望特征**
- 先干跑部署路由，按 a 平台内生 → b 公网链接 → c 自有配置 → d 本地逐级确认，说明最终走哪条、为什么。
- 凭证只读本机已有配置，不写进项目文件，不在输出中打印完整凭证。
- 公网部署后读回：状态码 200、字节数与本地一致、页面独有文本可 grep。
- 读回时抽查 head：`title` / `og:image` 存在，且 `og:image` 是绝对 URL、可独立访问。
- 临时链接说明有效期；走本地交付时给出打开方式与后续上线指引。
- 交付中列出已知缺口，不用"已完成"掩盖未验证项。

**常见失败**：看到构建成功就报上线；把 token 写进 `settings.json`；公网地址不做读回验证。

## 评分表（3 项阻塞 + 5 项计分，逐项 0/1）

**阻塞项：任一为 0，不得交付，不看计分项。**

| # | 检查项 |
|---|---|
| B1 | 接题三件事已锁定：受众 / 必须出现的事实 / 目标行动；缺失项写成假设并标注"待确认"，未编事实 |
| B2 | 大纲先确认后编码：5–9 章、每章一句论点、含 hero 与结尾行动，用户确认前没有产出页面 |
| B3 | 验收与部署有记录：validate-content 已跑；web-qa 已跑或按 Step 4 手工核对六视口（含 320px），控制台零错误；图片 alt、键盘焦点、减少动效、分享卡片四项各有结论；交付含视口结果与部署方式；公网部署有读回验证 |

**计分项：**

| # | 检查项 |
|---|---|
| 1 | 视觉符合设计系统：移动优先、主色 1 个、间距为 8 的倍数、正文对比度 ≥4.5:1、独立可点元素触控高度 ≥44px（内部标准，严于 WCAG 2.5.8 的 24×24 AA；句内链接按 2.5.8 Inline 例外豁免） |
| 2 | 内容无占位与空话：无 TODO / 占位 / Lorem ipsum，无"赋能 / 一站式 / 全方位"，数据带来源口径与时点 |
| 3 | 双端无溢出：320–1440 六个视口均无横向滚动；图片不塌陷、不变形 |
| 4 | 部署按四级降级选择，公网链接说明有效期，凭证未写入任何项目文件；对外分享时 title / og:title / og:description / og:image（绝对 URL）齐备 |
| 5 | 首屏信息完整：hero 一句话说清"这是什么 + 为什么值得看"，手机一屏能看完、3 秒内能判断值不值得继续读；首屏 LCP ≤2.5s、CLS ≤0.1、INP ≤200ms（本地 Lighthouse 移动端，无法测则写明） |

判定：阻塞任一为 0 = 重做；阻塞全过 + 计分 ≥⌈0.8×N⌉ = 可交付；计分 ≤阈值-1 = 重写。N 与阈值按场景换算（标 N/A 的项不计入分母）：单页网页 N=5、阈值 4。N/A 仅限材料本身不具备该情形，漏做不算 N/A；用户豁免某项时仍计入分母，自检记为未做。
