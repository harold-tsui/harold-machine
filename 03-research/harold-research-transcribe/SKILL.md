# Transcript Capture · 转写底稿

> 一句话：把"听过"变成"能引用、能定位到分秒、能看出哪里没听清"。

## 定位

L2 研究层的第 0 步：把不可检索的声音，变成可检索、可回听的文字。

| 做 | 不做 |
|---|---|
| 取音、转写、分段、打时间戳 | 观点提炼、结论归纳、立场评价 |
| 术语与数字抽检，标出不确定处 | 判断说话人"说得对不对" |
| 输出尽量贴近原话的文本 | 改写成书面语 / 去口语（→ `harold-production-polish`） |
| 记录转写方式、参数与实际覆盖范围 | 把听不清的地方猜成原文 |

- 交付物二选一（用户说了"字幕"就默认后者）：
  - **转写底稿**：研究 / 引用用，60 秒一段，带 `[mm:ss]`。
  - **字幕文件**：播放器 / 平台用，SRT 或 VTT，按字幕规范切条（见 Step 7）。
- 无论哪种，都必须附**校验记录**（怎么来的、哪里没把握）。
- 需要"这段访谈说明了什么" → 交给 `harold-research-brief` 在底稿上做证据分级；本技能不替它下判断。
- 判断标准：底稿里的每一行，第三方都能按时间戳回听到。

## 触发场景

- "这段 30 分钟访谈录音，帮我转成文字"
- "这个视频要文字稿 / 字幕不准，重转一份"（→ 默认走字幕路径）
- "帮我出个 SRT / 这条视频要能导入剪映的字幕"（→ 字幕路径）
- "播客整理成可搜索的笔记"
- "会议录音留下文字纪要的原始素材"（要观点归纳另走 `harold-research-brief`）
- "他大概第 12 分钟说的那句话，原文是什么"

## 工作流

### Step 0 环境自检（先跑一次）

- 检查 ffmpeg / ffprobe 与 ASR 引擎（faster-whisper / mlx-whisper / whisper.cpp）是否可用；命令见 `references/toolchain.md` §1。
- 同时确认能否跑**第二档模型或第二引擎**——这决定 Step 6 能否做交叉复核。
- 缺什么就报什么，并给出替代路径：用户自备转写文本、改用系统自带听写、分片抽听 / 人工补录。
- 只跑一次，装不上直接进降级路径，不循环重试安装。

### Step 1 立口径（先写，不跳过）

输出 8 行：素材｜来源与获取方式｜语言（单一 / 混语）｜时长｜用途（引用 / 检索 / 留档）｜**交付物（底稿 / 字幕 / 两者）**｜**保密级别**｜预计耗时与所需引擎。

保密级别不是填空，直接决定动作：

| 级别 | 强制动作 |
|---|---|
| 公开 | 无额外限制 |
| 内部（**用户未说明时的默认**） | 全程本地处理；不把原文贴给第三方服务；交付物不出现来源账号 |
| 受限 / 机密 | 只用本地链路，禁用云端 ASR；交付路径由用户指定，不落到共享目录；待核清单不抄敏感原文 |

用途同样不是填空，三档对应三种严格度：

| 用途 | 加到哪 |
|---|---|
| 引用 | 数字、日期、人名、机构**全部**进待核清单；每段都要能单独回听；不做任何口语清洗 |
| 检索 | 可另出一份无时间戳纯文本，但须标"检索用，未逐句校对"，且保留可回听的底稿文件 |
| 留档 | 需写完整性声明（覆盖区间与缺口）+ 原始文件名与文件哈希，便于日后对版本 |

任何时长开始前先报预计耗时，且要有依据：查 `references/toolchain.md` §14 的 RTF 基准表估算，或先跑 60 秒片段实测 RTF 再换算，报"区间 + 依据来源"。预计超过 10 分钟的分片执行并报进度。不要边跑边解释。

### Step 2 选路（先便宜后贵，顺序不可跳）

| 顺序 | 路径 | 何时用 |
|---|---|---|
| 1 | 平台 / 文件内嵌字幕 | 有官方或自动字幕，且抽 1 分钟核对能对上音频 |
| 2 | 本地语音识别（ASR） | 无字幕、字幕质量差、或素材本来就是音频 |
| 3 | 人工补录 | 上面都不通，或只有个别关键段落听不清 |

字幕 1 分钟就能验完，重转要几十分钟。跳过检查直接重转，是最常见的浪费。

走字幕路径且源有内嵌字幕、核对通过时，直接改写为 SRT 交付，不要重转。

### Step 3 取音

- 只取音频，不下载视频；统一为转写友好的采样格式（具体参数见 `references/toolchain.md` §4）。
- 本地文件先确认可解码：能读出时长与采样率再进入转写。
- 需登录的会员内容用已登录会话的 cookie；**不索要账号密码，不尝试绕过付费墙**，拿不到就转降级。

### Step 4 转写

- 模型档位按"能听清"选，不按"最好"选：清晰普通话用中档，口音重 / 术语密集 / 多人抢话才上调。
- 语言**显式指定**，不依赖自动检测；混语素材按片段标注，不强行统一。
- 术语场景给提示词：只放人名、机构、专有名词词表，不放整段话术（避免模型顺着提示词编内容）。词表优先从 `<工作区>/glossary.txt` 读，没有就现场建；转写后把新出现且已确认的高频专名追加回去（**需用户确认**，格式见 `references/toolchain.md` §13）。
- 长音频分片转写，逐片记录起始偏移，合并时加回。
- 中文素材若默认档错字明显，优先换**中文原生引擎**（Paraformer / SenseVoice 一类），再考虑 Whisper 升档：公开基准上中文 CER 差可达十个百分点级，但多为厂商自测，须用 60 秒片段实测确认（`references/toolchain.md` §5.5）。
- **记录本次实际用的引擎、模型档位与关键参数**（beam_size / vad / language），写进元信息，否则结果不可复现。

### Step 5 分段与时间戳（统一规则，逐条过）

1. 每行一段，行首 `[mm:ss]`；超过 1 小时用 `[h:mm:ss]`。
2. 段落边界优先取停顿（>1.5 秒静音）或说话人切换；引擎已给句级切分时直接沿用，不重切。单段 **≤60 秒**；中文另限 **≤200 字**，两者**先到为准**，超出时在最近的停顿或标点处断开（静音点取法见 `references/toolchain.md` §8）。
3. 短于 3 秒且少于 10 字的碎片，并入前一段，不单独成行。
4. 时间戳取该段起点，单调递增，首段为 `[00:00]`（字幕路径按 Step 7 的单独规则，不受此限）。
5. 音乐、掌声、纯噪音不转写，用 `[音乐]` / `[听不清]` 占位，不猜内容。
6. 未做声纹分离时，头部声明"未区分说话人"，不按语气猜"主持人 / 嘉宾"。
7. 说话人分离**默认不做**。仅在"用户明确要求 + 素材是 ≥2 人对话 + 结论需要引用到人"三条同时成立时才做：优先本地 diarization（见 `references/toolchain.md` §12），做不到就用问答结构人工粗标；机器分离结果必须标"机器分离，可能有错"，并抽 2 段核对。命中以下任一信号即判"分离不可靠"，退回"未区分"：同一人连续发言 20 秒内标签跳变 ≥2 次；与明显的问答结构矛盾；重叠说话段占比 >20%。宁可不分，不可乱猜。

### Step 6 质量校验（四层，逐层记录做了什么）

**A 结构检查（自动，必做）**
- 覆盖：末段时间戳与总时长差 ≤30 秒，或与最后一个有声段落结尾对齐；纯静音结尾不计入。
- 单调：时间戳无回退、无跳段。
- 重复：无整段复读（模型在静音处会循环输出同一句）。
- 空转：≤2 字且无意义的段列疑似幻觉；是否替换交 B 层按双条件判，不按字数直接删。

**B 置信度标记（自动，必做）**
- `avg_logprob < -1.0` 的段，句末标 `[?]` 并进待核清单。
- `no_speech_prob > 0.6` **且** `avg_logprob < -1.0`（两个条件同时成立）的段，判为静音幻觉，替换成 `[听不清]` / `[音乐]`。文本短不能单独作为判据，"好""对"这类正常短应答照常保留。
- 没有置信度字段的引擎（如 whisper.cpp 默认输出）跳过本层，并在校验记录里写明"该引擎无置信度输出"。

**C 交叉复核（自动，资源允许时必做）**
- 用第二档模型或第二引擎重跑同一音频，逐段比对；文本差异显著的段落进待核清单，标 `[?]`。
- 第二引擎优先选**异族**（Whisper ↔ 中文原生引擎）；同族升档只能算弱交叉，记录里注明。
- 分片交付时另做**接缝复核**：每个接缝取前后各 5 秒重转，与主稿比对，缺字或复读进待核清单。
- 有内嵌字幕时，用字幕作为第三方比对面。
- 两个结果都跑不了，明确写"未做交叉复核，单引擎结果"。

**D 人工复核（可选，只能由人做）**
- 输出**回听清单**：时间点 + 该处文本 + 疑点，交用户抽听（建议 5 处、每处 30 秒）。
- 用户回填后，把结论写进校验记录，给粗错字率。
- **agent 不得声称自己"回听"过音频。** 未做 D 就在交付物里写"未人工复核"，不得写成"抽样校验通过"。

数字与专名（金额、日期、人名、机构）始终进待核清单：对照画面 / 简介 / 上下文抽检，不确定处标 `[?]`。

### Step 7 出稿

按输出格式写。待核清单逐条给时间戳、原文、疑点、处理建议。

字幕路径额外规则（与底稿的分段规则不同，不要混用）：

- 每条 ≤7 秒、≥1 秒；每条最多 2 行；不跨句硬切。
- 行宽**按语言分档**，不把西文数字套到中文上：中文每行 **≤16 字**（SDH 场景可到 18）；西文每行 **≤42 字符**；中英混排折 **≤32 显示宽**（全角计 2、半角计 1）。建议值再低一档（中文 ≤14 字、西文 ≤37 字符），留安全边。
- 阅读速度比条长更硬：中文 **≤9 字/秒**（信息密集或 SDH ≤11），西文 **≤20 字符/秒**。超 CPS 就拆条或压停顿，不许靠拉长单条硬塞。
- 输出 `.srt`（或 `.vtt`）：SRT 用 `HH:MM:SS,mmm` 逗号分隔毫秒并带递增序号；VTT 用 `HH:MM:SS.mmm` 句点分隔，首行写 `WEBVTT`，序号可省。两种格式不可混用。
- 不做长段落合并；宁可条数多，也不要在播放器里溢出。
- 若只能给底稿（无字幕工具或时间不够），必须明说"这是文字稿，不是可导入的字幕"，并给转字幕的下一步。

### Step 7.5 外发前检查（素材不是本人录的，或要公开发布时）

三条都要过，缺一条就只做内部底稿：

1. **授权**：确认已获对方同意录制与引用；无法确认就在元信息写"授权状态：未确认"，且不接公开发布的下游动作。
2. **化名**：人名 `[人名A]`、机构 `[公司B]`、地点 `[地点C]`；真实身份的映射表单独存放，**不进交付物、不进共享目录**。
3. **范围**：保密级别为受限 / 机密时，一律不外发；即使对方口头同意，也先落到书面。

内部使用不做外发时，只需记录授权状态，后两条标"不适用（内部使用）"。

## 降级路径

| 触发条件 | 降级动作 | 交付变化 | 必须说明 |
|---|---|---|---|
| 无网络 / 不能用云服务 | 走全本地链路；模型已缓存则照常 | 无 | 数据未出本机 |
| 本地无模型且无法下载 | 退到最小可用模型或系统自带听写；再不行只做分段抽听 | 覆盖不全 | 列出未转写时段 |
| 内存 / 显存不足 | 降模型档位 + 分片 + CPU 低精度 | 质量下降 | 标注实际档位 |
| 只能跑一个引擎 | 跳过交叉复核，只做 A+B | 置信度覆盖变窄 | 写"单引擎，未交叉" |
| 无人可回听（纯 agent 交付） | 只出回听清单 | 无错字率结论 | 写"未人工复核" |
| 长音频（>60 分钟） | 按静音切 10–15 分钟分片，偏移合并 | 接缝可能丢 1–2 秒 | 标出接缝时间点 |
| 非中文 / 多语混杂 | 显式指定主语言，逐片复核；低置信片段标 `[?]` | 部分段落不可靠 | 按段标注语言 |
| 素材不可获取（DRM / 地区 / 需登录） | 不绕过，改为索取原始文件或等价材料 | 无底稿 | 写"不可获取 + 原因 + 替代方案" |

硬规则：降级必须写进交付物，不能把降级结果包装成完整底稿。降级交付时附一条补齐命令：装好依赖或联网后可直接执行，用来补转未覆盖时段。

## 验收标准

**阻塞项（任一为 0，整份不可交付）**

- [ ] B1 不伪造：无音源不出正文；不编时间戳、不编听不清处的内容、不声称执行过没做的校验（尤其"回听"）；交付物不出现个人绝对路径、账号、密钥
- [ ] B2 可回听：底稿每行单调递增时间戳、首段 `[00:00]`；字幕首条从第一个有声点起、序号从 1 递增；末段与总时长差 ≤30 秒，或与最后一个有声段落结尾对齐（纯静音结尾不计）
- [ ] B3 不越界：不添加转写者自己的观点、评价、总结性结论；受访者观点按原话保留并标为「他说」；越界请求已转交下游

**计分项（0/1）**

- [ ] 1 口径 8 项先于执行写出，含交付物类型、保密级别与用途对应的严格度
- [ ] 2 元信息含引擎·档位·参数·分片偏移·耗时·完成度·校验层级
- [ ] 3 分段符合规则：碎片并入前段、单段 ≤60 秒且中文 ≤200 字、静音与噪音用占位不猜
- [ ] 4 置信度层已执行，`[?]` 有依据；疑似幻觉已替换
- [ ] 5 交叉复核已执行或已写明未做及原因；分片交付时接缝已复核
- [ ] 6 待核清单具体到时间戳、疑点与来源
- [ ] 7 保密与外发动作已执行：受限素材未走云端、未落共享目录；引用非本人素材前已确认授权并化名，映射表未进交付物
- [ ] 8 降级显式记录，完成度与未覆盖时段写清
- [ ] 9 字幕路径触发时产出可导入的 SRT/VTT，且符合条长、行宽（按语言分档）与阅读速度（CPS）限制；未触发记 N/A

判定：阻塞任一为 0 = 重做；阻塞全过 + 计分 ≥⌈0.8×N⌉（N 为计分项数，N/A 不计入分母；满项 N=9，阈值 8；字幕未触发时 N=8，阈值 7；完全无正文时 N=6，阈值 5；两者同时 N=5，阈值 4）= 可交付；计分 ≤阈值-1 = 重写。

## Gotchas

1. **有字幕还去重转**
   以半小时素材为例，重转通常多花数十分钟，结果往往还不如官方字幕。先花 1 分钟查字幕再说。

2. **静音处循环幻觉**
   长静音、片头片尾、背景音乐段，模型会复读同一句或编出整段话。检测重复 + 静音过滤，宁可用 `[音乐]` 占位。

3. **把猜的写成原文**
   人名、机构、数字最容易"顺耳编造"。听不清就写 `[听不清]`，标 `[?]` 进待核清单，不许脑补。

4. **分片后忘加偏移**
   每片时间戳从 0 开始，合并后全稿错位。偏移量必须逐片记录并加回，交付前检查单调性。

5. **语言自动检测误判**
   中英混说时容易整段判成英文，输出成音译或翻译混杂。显式指定语言，混语按段标。

6. **顺手总结观点（最容易被诱导的越界）**
   用户说"顺便总结一下"，可以给"带时间戳的原话索引"，不下结论。结论属于 `harold-research-brief`。

7. **声称"已回听"却没有记录（最危险的一条）**
   agent 没有耳朵。任何"抽样回听、错字率 5%"的表述，如果没有用户的回填记录，就是伪造。只写自己能做的：结构检查、置信度、交叉比对；人耳结论必须注明来源。

8. **把底稿当字幕交付**
   60 秒一段的底稿导入播放器会满屏溢出。用户要字幕就给 SRT，给不了就说明并给转换路径，不要含糊过去。

9. **长音频估时不足**
   CPU 转写耗时与素材时长同量级，机器差异很大。先报时再开工，报区间而不是一个数（依据见 `references/toolchain.md` §14），避免中途被叫停；有硬件加速要用。

10. **把西文的行宽和语速套到中文上**
    42 字符/行、20 字符/秒是西文标准；中文标准是 16 字/行、约 9 字/秒。照 42 显示宽排中文等于每行 21 个汉字，播放器必溢出，观众也读不完。

11. **未经授权就把别人的录音转成可发布内容**
    授权、化名、映射表隔离三件事缺一件，就只能停在内部底稿。事后补救比事前确认贵得多。
