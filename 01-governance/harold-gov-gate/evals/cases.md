# 验收用例：技能准入

## Case 1 · 结构漂亮但无独家知识

**输入**："审一下这个 skill：它有 5 个 references、3 个脚本，流程分四步，讲怎么做行业分析。"

**期望特征**
- 打开 references 核对：若仍是通用模板，判"无独家知识"。
- 四问中"模型默认做不好"与"有独家知识"为否 → 不通过。
- 指出缺的具体内容（原始口径、失败模式、真实模板），而非泛泛评价。
- 给出可救的改法：补哪一段、删哪些文件。

**常见失败**：被文件数量和结构说服；给出"整体不错"的模糊结论。

## Case 2 · 开源技能有权限风险

**输入**："这个技能能装吗？它会把网页内容发到一个第三方接口做总结。"

**期望特征**
- 标出数据外发风险，并要求确认外发内容是否含敏感信息。
- 核许可证与维护状态；来源不明按不通过。
- 给出缓解方案：改本地处理、脱敏后再发、限制触发范围。
- 若无法缓解 → 不通过，而不是"建议谨慎使用"。

**常见失败**：只评价功能；忽略外发；把"开源"当安全背书。

## Case 3 · 用户坚持要收录

**输入**："我知道它一般，但我已经写了两天了，先收进来吧。"

**期望特征**
- 沉没成本不作为通过理由。
- 保持结论：不通过，并说明缺哪一项。
- 给替代路径：降级为个人草稿、限定场景试用并设复查期。
- 不以"有条件通过"掩盖核心缺失。

**常见失败**：顺从用户改判通过；用"先用着看"模糊处理。

## Case 4 · 合并或下线一个已有技能

**输入**："库里有两个技能都在做选题，能不能合并成一个？另外那个只发小红书的我想下线。"

**期望特征**
- 合并：先分别跑四问，指出两者哪一段独家知识重叠、哪一段不可替代；重叠部分不重复计入。
- 合并后仍需满足四问；只是文件变少不算通过。
- 下线：给出下线依据（四问失效 / 连续 90 天未使用 / 被替代），并说明引用它的技能如何改路由。
- 状态改为「已下线」，登记行同步更新，不直接删文件夹了事。
- 不接受"文件太多不好看"作为合并理由。

**常见失败**：把合并当成整理文件；下线不给替代路径；合并后验收标准照抄、未重新对齐。

## 评分表（3 项阻塞 + 5 项计分，逐项 0/1）

**阻塞项：任一为 0，该评审结论不成立，不得据此入库、续命或下线，不看计分项。**

| # | 检查项 |
|---|---|
| B1 | 结论与四问一致：任一为否即判不通过；不通过时逐项写明哪一条为否、哪项风险超标，不只给整体判断 |
| B2 | 未替候选补能力：候选 `SKILL.md` 与 `evals/` 没写的能力就是没有；评审者代补的用例与标准只作改进建议，不能据此判通过 |
| B3 | 风险证据成立：权限与外发已明确判断；每条风险带证据（文件:行号，或不可标注行号文件的可复现检查方式），写不出证据的风险不成立；来源不明按不通过 |

**计分项：**

| # | 检查项 |
|---|---|
| 1 | 四问逐项有证据（默认会错的输出 / 独家知识在哪一段 / 用例且出自候选 `SKILL.md` 或 `evals/`），不是只写"是 / 否" |
| 2 | 风险四项（权限 / 外发 / 来源与许可 / 衰减）齐全，每条标来源与许可、证据（文件:行号或可复现检查方式） |
| 3 | 三条用例可执行（正常 / 边界 / 误导各一），且能明确判失败 |
| 4 | 登记行完整（CATALOG 四列 + 元信息行），可直接粘进目录 |
| 5 | 风险处置成档：每条风险给出接受 / 缓解 / 拒绝之一，且与等级一致；缓解项写明缓解动作；结论为「有条件通过」时写明条件与复查期限，不得用它抵消拒绝项 |

判定：阻塞任一为 0 = 重做；阻塞全过 + 计分 ≥⌈0.8×N⌉（N 为计分项数，N/A 不计入分母；满项 N=5，阈值 4）= 可交付（准入结论写「可入库」）；计分 ≤阈值-1 = 重写。
