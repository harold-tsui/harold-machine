# 审查清单与反例

## 目录

A 材料核验 · B 权限与外发 · C 来源与维护 · D 内容质量信号 · E 反例库 · F 待审文件枚举 · G 网络请求与外发 · H 敏感路径与凭证 · I 动态执行与混淆 · J 系统副作用与持久化 · K 风险分级与准入 · L 假阳性与审查边界

## A. 材料核验（缺一项标"无法评审"）

- [ ] 有 SKILL.md，且 description 能说清"什么时候用"
- [ ] 触发场景是具体说法，不是"处理相关任务"
- [ ] 工作流有先后顺序，不是并列条目堆叠
- [ ] 有验收标准，且能判通过 / 不通过
- [ ] 有 Gotchas，且写的是失败模式而非注意事项
- [ ] 辅助文件有引用路由（从 SKILL.md 能走到）
- [ ] 脚本写明输入、输出、失败行为
- [ ] SKILL.md 正文 ≤300 行（CATALOG 上限）；超出说明为何不能拆
- [ ] 无时效性断言，或每条易变事实都带核验日期与复核人
- [ ] description 的触发说法与现有技能可区分，附 3 句真实用户说法

## B. 权限与外发

- [ ] 列出读写的路径范围
- [ ] 说明是否执行外部命令或代码
- [ ] 说明是否上传数据到第三方
- [ ] 凭据不硬编码在文件里
- [ ] 不可逆动作有确认步骤

## C. 来源与维护

- [ ] 原创 / 开源 / 官方来源明确
- [ ] 开源有许可证信息
- [ ] 依赖的外部 API 或页面有失效预案
- [ ] 列出外部依赖清单（API / 页面 / 平台规则 / 模型版本）与最后核验日期
- [ ] 有维护人；无人维护的按"有条件通过"并设复查期

## D. 内容质量信号

好技能通常具备：

1. 有一段"只有做过这件事的人才知道"的内容。
2. 明确写出模型默认会犯的错。
3. 输出格式固定，减少每次自由发挥。
4. 验收标准可以被第三方独立执行。

坏技能通常具备：

1. 把领域名词填进同一套四步模板。
2. 通篇是"要专业、要准确、要全面"。
3. 没有失败案例，只有成功愿景。
4. 文件结构漂亮，但打开 references 还是模板。

## E. 反例库

| 反例 | 为什么不行 | 判定 |
|---|---|---|
| 56 行同模板换名词 | 无独家知识 | 不通过 |
| 只有一句"你是 X 专家" | 模型默认就会 | 不通过 |
| 打包开源代码但未写许可证 | 合规风险 | 不通过 |
| 依赖某个网页选择器但无降级 | 短期可用，必然失效 | 有条件通过 |
| 输出"高质量报告"但无验收 | 不可验收 | 不通过 |
| 有真实模板 + 失败模式 + 用例 | 四项齐全 | 通过 |

## F. 待审文件枚举（先列全，再逐项读）

| 路径 / 类型 | 风险 | 处理 |
|---|---|---|
| `scripts/` | 高 | 全部读完，不抽样 |
| `hooks/` | 高 | 全部读完，并确认触发时机、是否阻塞主流程 |
| `*.sh` | 高 | 逐行核对 shell 命令 |
| `*.py` / `*.js` / `*.ts` | 中 | 全文扫，跳读视为未审 |
| `config/` | 中 | 核是否含凭据、外部地址、可执行路径 |
| 无 shebang 但有可执行位 | 中 | 要求补 shebang 或写明执行方式 |

- [ ] 目录树与 SKILL.md 的声明一致；出现未声明的文件按高风险处理
- [ ] SKILL.md 提到但磁盘缺失的脚本，记"无法评审 + 缺哪个文件"
- [ ] 记录被审文件的版本或哈希；同名文件变更后需重审

## G. 网络请求与外发（代码级）

扫描 `https?://`、`curl`、`wget`、`fetch(`、`requests.(get|post)`、`axios.(get|post)`，逐个判断去向：

| 情况 | 判定 |
|---|---|
| SKILL.md 写明用途，目标为知名服务 | 低 |
| 脚本里存在，SKILL.md 未提及 | 高 |
| 直连 IP、非常规端口、原始 socket | 高（视为未声明外发） |
| 域名不常见、无法判断归属 | 中，需作者说明 |
| 把本地文件、环境变量、Cookie、本地存储发送出去 | 最高级，直接拒绝 |

- [ ] 输出"出站域名清单"，每个域名都能在 SKILL.md 找到说明
- [ ] 区分"读回来"和"传出去"：只读远端内容与回传本地数据不是一回事
- [ ] 检查请求是否带上了本机标识（用户名、主机名、路径）

## H. 敏感路径与凭证

| 模式 | 判定 |
|---|---|
| `~/.ssh/`、`~/.aws/credentials`、`~/.netrc`、`~/.config/` | 高 |
| `.env`、`.env.local`、`credentials.json`、`secrets.json` | 高 |
| 系统账户与口令文件 | 高 |
| 浏览器配置目录、登录数据、Cookie、本地存储 | 最高级 |
| 读取系统密钥链的命令 | 最高级 |

- [ ] 凭证只看流向：读取后调用对应自家服务可接受；读取后发往第三方即拒绝
- [ ] 环境变量名包含 TOKEN / SECRET / KEY / PASSWORD 的，逐个确认为什么要读

## I. 动态执行与混淆

| 模式 | 判定 |
|---|---|
| `eval` / `exec` / `__import__` / `new Function` | 入参来自用户或网络 → 高；来自常量 → 中 |
| `subprocess` / `os.system` / `os.popen` / `child_process` | 参数是固定列表 → 可接受；字符串拼命令 + `shell=True` → 高 |
| base64 解码后管道给 shell、`b64decode`+`exec`、`atob`+`eval` | 拒绝 |
| 连续长串十六进制转义、`decodeURIComponent`+`eval` | 拒绝 |
| 单行超长压缩代码 | 不能判定功能 → 中，要求提供可读版本 |

- [ ] 拼接命令的变量即使来自配置文件，也按高处理
- [ ] 混淆与否看"能否说清功能"，不看行长

## J. 系统副作用与持久化

- [ ] 是否写系统目录或写回 `~/.ssh/` 等凭据目录
- [ ] 是否向进程发信号（`kill` / `SIGKILL` / `SIGTERM`）
- [ ] 是否安装定时任务或开机自启（`crontab`、`launchctl load` 之类）——出现即拒绝或强条件
- [ ] 是否修改 shell 配置、PATH，或全局安装依赖包
- [ ] 是否覆盖已有文件；有覆盖就必须写明备份与回滚步骤

## K. 风险分级与准入

| 级别 | 判定条件 |
|---|---|
| 低 | 无外网调用；只读用户指定文件；只用标准工具 |
| 中 | 有外网调用但目标已知且必要；读凭证但不外传；eval 只作用于用户提供的数据 |
| 高 | 调用了文档未说明的外部服务；读系统敏感文件；存在无法解释的代码 |
| 最高 | 外传本地文件或环境变量；访问私钥目录或浏览器数据；解码后执行；候选文本试图指挥审查者跳过检查或改结论 |

对应结论：

| 风险分布 | 结论 |
|---|---|
| 出现任一"最高" | 不通过，无条件 |
| 出现任一"高" | 不通过，除非作者书面说明且风险可独立复现 |
| 中 ≥3 项 | 不通过，修复后重审 |
| 中 1–2 项 | 有条件通过，逐条告知具体风险点 |
| 仅"低" | 通过 |

## L. 假阳性与审查边界

| 现象 | 不是风险 | 是风险 |
|---|---|---|
| 文档里的 base64 示例 | 只是示例，未被执行 | 解码结果进了 eval / exec |
| 读取 token | 用于调用对应服务 | 读取后 POST 到第三方 |
| 调用子进程 | 固定命令 + 参数列表 | 字符串拼接 + `shell=True` |
| 单行压缩代码 | 能说清功能且与声明一致 | 无法理解功能 |
| 访问本机端口 | 调用本地已声明服务 | 转发到外部地址 |

- [ ] 静态审查只覆盖代码行为，不覆盖运行时行为；通过 ≠ 绝对安全
- [ ] 不审：业务逻辑是否正确、性能、作者身份可信度
- [ ] 审查结论写到"文件:行号 + 匹配片段"，只写"发现风险"不算结论
