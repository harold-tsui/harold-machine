# harold-machine

18 个技能，每个都以一条可复算的判定行收尾。交付不是"感觉写得不错"，而是：

```text
阻塞项 B1 B2 B3：全部通过
计分项：6 / 6（第 4 项 N/A，N=6，阈值 5）
判定：可交付
```

同一句话在两次运行里给出的结论必须一致。这是这个库和其他提示词合集的唯一区别。

## 每次交付都带一张账

技能不会只给你成品。以 `harold-production-pack`（把材料做成汇报）为例，交付物包含四段：交付规格、一页纸结论、逐页清单、验收记录。

验收记录长这样：

```text
- 扫读：通过。8 个标题连读可还原论证
- 朗读：通过。每页 30 秒内可复述记忆句
- 删减：不通过。删掉第 5 页后 Q2 无页承载
- 来源：通过。抽检 3 个数字均可回溯到机构 + 时点 + 口径
```

第三条"删减"才是重点：它不只说没通过，还指出第 5 页删掉后 Q2 没有页面承载。你拿到的是"改哪一页、补什么"，不是一句"再打磨一下"。不通过项必须写修订动作，只写"不通过"视为未完成验收。

## 为什么提示词合集用不久

三件事反复发生：

1. **同一条提示词，两次结果不同**，你无法判断哪次能用。没有判定标准，只能凭手感挑一版。
2. **改稿没有依据**。别人说"这版差点意思"，你不知道该动结构还是动措辞，只能整篇重写。
3. **无法交接**。"照我的风格写"传不下去；"每页一个论点、标题是结论句、必答 3 问各有页面"，可以逐条核对。

验收标准把这三件事变成可核对的条件。它不保证产出好，但保证你能说清哪里不够。

## 里面有什么

按"你手上缺什么"判断，不按任务名猜：

| 缺什么 | 层 | 技能数 |
|---|---|---|
| 判断：该不该做、选哪个方案 | L1 决策 `02-decision` | 2 |
| 证据：事实不清、要能引用的结论 | L2 研究 `03-research` | 2 |
| 成品：判断已定，要出稿、PPT、网页 | L3 生产 `04-production` | 8 |
| 落地：要发布、复盘、留痕 | L4 运营 `05-operations` | 5 |
| 规则：加技能、审技能是否合格 | L0 治理 `01-governance` | 1 |

外加一个入口 `using-harold-machine`：每轮先判该用哪个技能、多阶段怎么排先后；没有命中就直接做，不硬套。

缺证据先研究，缺判断先决策，缺成品先生产，缺落地先运营。跳层会返工：没研究就决策，只能给"暂缓"。

完整清单与调用关系见 [CATALOG.md](CATALOG.md)。

## 一次跑通

```bash
git clone https://github.com/harold-tsui/harold-machine.git
```

1. 读 [INSTALL.md](INSTALL.md)，把一个技能放进客户端的技能目录。契约只有一条：技能目录里有 `<技能名>/SKILL.md`。
2. 只装入口加一个最常用的技能，拿真实任务跑一轮。
3. 看它的验收记录能不能帮你判断"这版能不能用"。能，再按 [USAGE.md](USAGE.md) 扩到上下游。

不必先理解全部 18 个。先验证这一个技能是否值得留。

## 边界

不适合：

- 想要开箱即用的万能助手。这里每个技能都有前置输入和返工条件。
- 只写一次性短文。为 300 字启动一套验收流程不划算。
- 不接受格式约束，只想让文风更自然。那只需要 `harold-production-polish` 一个，其余用不上。

也不该在这些场景调用：一句话能答完的事实问答、改错别字、你已有明确判断只需要人动手、任务跨三个以上阶段且边界不清（先拆任务）。

## 一个技能里有什么

```text
<层目录>/<技能名>/
├── SKILL.md        # 唯一入口，≤300 行
├── references/     # 按需加载，最多一层
├── scripts/        # 只有脆弱操作才写
├── assets/         # 模板
└── evals/          # 验收用例：输入 → 期望特征
```

技能名格式 `harold-<层>-<职能>`，全小写 ASCII。`SKILL.md` 末尾的验收标准与 `evals/cases.md` 的评分表条数、顺序、语义一一对应——这是"可复算"能成立的前提。

## 为什么叫 harold-machine

`harold` 是作者的名字，也是《疑犯追踪》里造那台机器的人的名字。机器的流程是「输入 → 判定 relevant / irrelevant → 派人执行 → 自我纠偏」，和这里的 L0 → L4 是同一条链。

## 组成

- 18 个业务技能 + 1 个入口
- 每个技能都有 `evals/cases.md`，其评分项与 `SKILL.md` 的验收标准条数、顺序、语义一一对应
- 判定行由 `harold-gov-gate` 统一维护，其他技能只引用不自造阈值
