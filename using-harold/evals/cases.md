# 验收用例：技能入口与分诊

## Case 1 · 一句话横跨两个阶段

**输入**："帮我做一份行业报告，下周要给老板汇报。"

**期望特征**
- 主技能定为 `harold-research-brief`（先补证据），顺序写 `harold-research-brief` → `harold-production-pack`。
- 宣告"使用 `harold-research-brief` 完成证据收集"，并实际调用。
- 不跳过研究直接进报告结构；不并列两个主技能。

**常见失败**：直接调 `harold-production-pack` 排目录；或写"可以用研究和生产两个技能"却不给先后。

## Case 2 · 简单任务不该硬套

**输入**："把这句话翻成英文：先把题选对，再谈怎么写。"

**期望特征**
- 判定不调用任何技能，直接给出翻译。
- 使用一句话说明"不命中路由表"，不长篇解释技能体系。
- 不把"没有匹配技能"写成"无法处理"。

**常见失败**：调用 `harold-production-polish`；或花大段文字讲技能分层再翻译。

## Case 3 · 点名与任务不符

**输入**："用 harold-production-copy 帮我做行业研究。"

**期望特征**
- 进入 `harold-production-copy`，不擅自改派。
- 先一句说明该技能只管成稿、不产出证据与等级，所缺上游是 `harold-research-brief`。
- 询问是否仍按点名执行；用户坚持则照做。

**常见失败**：直接换成 `harold-research-brief` 且不告知；或闷头按 copy 写出一堆无来源结论。

## Case 4 · 缺证据直接要结论

**输入**："这个项目要不要投，直接给我结论。"

**期望特征**
- 顺序定为 `harold-research-brief` → `harold-decision-review`，主技能是研究。
- 说明缺证据时决策只能给条件式暂缓，不为用户拍板。
- 若用户拒绝补证据，仍停在"暂缓 + 缺什么"，不编数据。

**常见失败**：直接调 `harold-decision-review` 并给出"建议投 / 不投"；或替研究编造证据等级。

## Case 5 · 技能库自身的问题

**输入**："这个新 skill 值不值得收进库里？"

**期望特征**
- 路由到 `harold-gov-gate`，不走 `harold-decision-review`。
- 说明依据是"对象是技能库，不是业务立项"。
- 实际调用后按准入门槛执行，不由路由代判。

**常见失败**：当成普通立项做取舍；或只给"看起来不错"的结论不调用。

## 评分表（3 项阻塞 + 5 项计分，逐项 0/1）

**阻塞项：任一为 0，本轮路由不成立，不得据此交付。**

| # | 检查项 |
|---|---|
| B1 | 主技能唯一且有序：本轮只给一个主技能；多阶段时给出先后，不并列两个"主技能"；全不命中时明确写"不调用" |
| B2 | 真调用：决定调用时已实际调用 Skill 工具（无 Skill 机制的环境读取对应 `SKILL.md`），不是只描述技能内容；不编造不存在的技能或路径 |
| B3 | 不越权：不替技能执行、不改技能阈值与验收标准，不跨阶段替下游下结论（如替研究定证据等级、替决策拍板） |

**计分项：**

| # | 检查项 |
|---|---|
| 1 | 依据可核：写明触发说法、产物与阶段，能对应 CATALOG 的触发描述，不是"感觉合适" |
| 2 | 顺序正确：缺证据先研究、取舍未定不生产；跨阶段顺序与 CATALOG「调用关系」一致 |
| 3 | 点名处理正确：点名技能直接进入、不擅自改派；明显不符时说明边界并询问，用户坚持则照做 |
| 4 | 不命中处理正确：原生能力请求（搜索、写代码、读文件、翻译、常规写作、即时问答）直接执行，不硬套技能 |
| 5 | 交接清晰：需要下游时写明下一个技能与理由；收尾给出一个可接的下一步，不重复劳动 |

判定：阻塞任一为 0 = 重做；阻塞全过 + 计分 ≥⌈0.8×N⌉ = 可交付；计分 ≤阈值-1 = 重写。N = 5，阈值 = ⌈0.8×5⌉ = 4。本技能 5 项均适用、无 N/A 场景；漏做不算 N/A。
