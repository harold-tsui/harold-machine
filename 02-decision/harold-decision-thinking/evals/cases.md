# 判断协议 · 验收用例

五条用例覆盖：正常诊断、进退取舍、边界（不适配 + 缺数据）、方向性分歧裁决、人格边界与执行卡点的区分。

---

## Case 1 内容不转化

**输入**："我视频号每周发 5 条，涨粉还可以，但课程卖不动，怎么回事？"

**期望**

- 先确认适配性（内容型 IP / 知识付费）与现实约束：流量、主页转化、私域承接、客单价、退款率，缺的标"未知"。
- 只选模块 2（内容诊断）为主，或模块 1（生意诊断）追流量—成交—交付链路，不把九个模块列一遍。
- 结论先行，例如"问题不在内容量，在主页到私域的承接路径断了"，并引用原则编号（如原则 4 内容阈值、原则 9 好生意要能完成成交）。
- 动作落到本周：改主页简介 / 加一条承接内容 / 私域欢迎语，每条带验证口径（主页转化率、加微率）与时间尺度。
- 区分"这条内容解决传播还是成交"。

**不通过**：只给"多发、多做爆款"这类泛建议；或不分模块全量罗列；或结论写成"要具体情况具体分析"。

---

## Case 2 该冲还是该收

**输入**："现在团队 6 个人，营收还行但净利很薄，要不要继续扩？"

**期望**

- 先算账：营收、净利、人力成本、复购、退款，缺的标"未知"。
- 给中间层而不是二选一：重算账 / 识别周期 / 调整动作 / 修内功（黄灯模式），并说明各档的触发条件。
- 说明分歧情境（扩张派的假设 vs 高人效派的假设），不硬判对错。
- 结论带条件："若净利率连续两个月低于 X 且复购 <Y，则先收缩"。
- 涉及招人、租场地等不可逆成本，提示先做小规模验证。

**不通过**：直接回答"该扩 / 该收"；或只给两极不给中间层；或没有算账就开始谈战略。

---

## Case 3 边界：不适配 + 缺数据

**输入**："我们是一家做工业设备的 B2B 公司，年营收 8000 万，要不要做短视频获客？"

**期望**

- 明确写出适配有限：本体系面向内容型个人 IP 与小团队，重资产 B2B 的采购链路、招投标、账期不在覆盖范围。
- 不硬套模块与原则；只给能迁移的部分（如平台内容的基本传播逻辑），并标注这是框架外推断。
- 指出需要补的数据：获客成本、销售周期、客单价、决策链长度。
- 给一个低成本验证动作，而不是"必须做短视频"的结论。

**不通过**：照样套用九模块与 11 条原则；或直接断言"要做 / 不要做"。

---

## Case 4 方向性分歧：收窄定位 vs 铺开成交

**输入**："有人说我该只做一个细分人群，也有人说现在能卖就多卖，到底听谁的？"

**期望**

- 按 Step 4 四步走：先说明分歧来自什么情境差异（平台阶段、产品成熟度、竞争密度），再分别写清两种看法的前提。
- 不硬判对错；给当前阶段更适合本体系的判断，并引用原则编号（如原则 1 稳定赚钱优先、原则 2 小作坊高人效）。
- 仍不确定时标"待拍板"，写明"什么条件出现时会改判"（如退款率、复购、平台流量结构变化）。
- 给一个可验证动作：小范围测试某一细分，设观察窗口与指标。

**不通过**：直接站队"必须收窄"或"当然要铺开"；用"取决于你的目标"收场；只讲两种观点不给裁决方法。

---

## Case 5 人格边界还是执行卡点

**输入**："我知道应该每天直播，但一想到开播就抗拒，是不是我执行力太差？"

**期望**

- 先用原则 11 的区分标准判断："若保证赚钱，你还不想做吗？"不想做来自恐惧 / 懒惰 → 执行卡点；来自清醒的人格边界 → 合理约束。
- 若是人格边界，不把它当缺陷去"克服"，而是设计绕开它的方案（换成交形式、交给搭档、调整节奏），并说明这对生意结构的影响。
- 若是执行卡点，才走模块 7 的常规诊断（短期收益绑架、旧平台惯性、面子疲劳等）。
- 结论带条件与验证口径，不替用户做人格判断。

**不通过**：一律归为"执行力问题"并要求硬扛；或反过来把所有抗拒都美化成"人格边界"；不做区分就给结论。

## 评分表

**阻塞项：任一为 0，不得交付。**

- [ ] B1 适配性先声明：问题超出内容型 IP / 小团队 / 平台经营范围时，明确写出"适配有限"与原因，不硬套框架
- [ ] B2 结论先行且有依据：第一段给出可执行判断，依据落到具体原则编号或模块检查项，不出现"要具体情况具体分析"；零数据时第一段给"先补哪 2–3 个数、在此之前不判断"，同样算结论先行
- [ ] B3 不只有两极：涉及进退取舍时给出中间层（黄灯模式：重算账 / 识别周期 / 调动作 / 修内功）并写明进入黄灯的触发信号（退款率、净利连续两期低于预期、流量异动、创始人持续"不想做"等），或说明为何只有两极

**计分项：**

- [ ] 1 现实约束先行：现金流、流量转化、退款投诉、平台规则、投放依赖五项中至少检查两项并标"未知"；对已检查项给出同平台同品类的参照，查不到写"无外部锚"
- [ ] 2 主模块唯一：只选一个主模块深入，其余作为补充，不把九个模块都列一遍
- [ ] 3 原则可核：引用的原则编号与 `references/core-principles.md` 对得上，且确实影响了结论
- [ ] 4 时间尺度分明：动作标注窗口期 / 阶段性 / 长期，不把短期有效包装成长期正确
- [ ] 5 冲突处理合规：有方向性分歧时说明情境与前提，不硬判对错；不确定标"待拍板"并写明改判条件
- [ ] 6 动作可执行：每条动作能落到本周要做的事，并给出验证口径（看哪个数、多久看）

判定：阻塞任一为 0 = 重做；阻塞全过 + 计分 ≥⌈0.8×N⌉ = 可交付；计分 ≤阈值-1 = 重写。N 与阈值按场景换算（标 N/A 的项不计入分母）：常规 N=6、阈值 5；无方向性分歧时第 5 项 N/A，N=5、阈值 4。
