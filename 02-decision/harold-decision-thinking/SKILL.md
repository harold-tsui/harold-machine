# Decision Thinking · 内容生意的判断协议

> 一句话：先看能不能赚、能不能活、风险在哪，再谈更高层的对错。

## 核心定位

- 适用：内容型个人 IP、知识付费、小团队、直播成交、平台化经营。
- 不适用：传统 SaaS、纯电商供应链、重资产公司、复杂 B2B 组织——遇到这类问题先说明"本体系适配有限"，再给能给的判断。
- 与 `harold-research-brief` 的分工：这里给判断，不给事实。缺数据时先要数据，不靠框架硬推。
- 与 `harold-ops-finance` 的分工：算账口径（收入确认、CAC/LTV、退款后收入）走 finance；本技能只把数字用于判断，不另造口径。
- 与 `harold-decision-review` 的分工：这里诊断生意卡点、给方向与中间层；那里走完整决策程序（选项、假设、基准率、条件式结论、复盘记录）。需要对簿公堂式取舍或要留决策记录时转 review。
- 默认立场：稳定赚钱优先于抽象正确；小作坊高人效优先于扩张。

## 触发场景

- "帮我诊断这个生意"
- "内容为什么不转化"
- "直播为什么卖不动"
- "该冲还是该收"
- "这个动作有没有平台风险"
- "这个报价 / 训练营怎么设计"

## 工作流

### Step 0 适配性检查

三问各一句话，答不上来就先问，别急着分析：

1. 这是内容型个人 IP / 知识付费 / 小团队生意吗？不是就说明适配有限。
2. 问题卡在哪一层：现实约束（流量、转化、合规）还是更高层判断（定位、组织、战略）？
3. 手上有没有可判断的数据？没有就先列出最低需要的两三个数。

### Step 1 现实约束先行

先看这五项里已知哪些，缺的标"未知"：现金流与净利、流量与转化、退款与投诉、平台规则与词汇红线、投放依赖度。

再找一个外部参照类：先查 `references/modules.md` 模块 1 的经验区间表，再按同平台、同品类、同阶段替换为更贴近的转化率、退款率、复购与获客成本基准。都不匹配就写"无外部锚"，不要只用自己的数。

很多"战略问题"本质是流量、品退、商品词、平台风控的问题。先看现实，再谈高层。

### Step 2 选一个主模块

只选一个主模块，其余作为补充检查项。九个模块的完整检查清单见 `references/modules.md`。

| 模块 | 用户这么说时选它 | 优先看什么 |
|---|---|---|
| 1 生意诊断 | "生意卡住了""不赚钱" | 流量—成交—交付—复购哪一段断 |
| 2 内容诊断 | "内容不涨粉 / 不转化" | 是否跨过质量阈值，而非发布频次 |
| 3 直播成交诊断 | "直播卖不动" | 人货场与承接路径，不比单场 GMV |
| 4 产品与报价 | "定价 / 训练营 / 课程怎么设" | 产品角色、矩阵位置、纯度、门槛 |
| 5 平台风险与合规 | "有没有风险""被限流" | 违禁词、商品词、详情页、投诉路径 |
| 6 战略取舍 | "该冲还是该收" | 当期利润 vs 长期资产，先算账 |
| 7 执行卡点 | "推不动""执行不下去" | 先分清是恐惧懒惰，还是人格边界 |
| 8 概念拆解 | "XX 到底是什么意思" | 拆到可判断、可执行的定义 |
| 9 AI 与流程设计 | "怎么用 AI 提效 / 无人化" | 能不能写成可转交的 SOP |

### Step 3 取原则

从 `references/core-principles.md` 的 11 条里挑 2–3 条真正影响本次结论的，写明编号与一句话依据。挑不出对应原则时，说明"本次判断不依赖既有原则"，不用凑。

关键几条先记住：稳定赚钱优先于抽象正确（1）；小作坊高人效（2）；直播成交是现阶段核心资产（3）；内容要跨阈值不是堆频次（4）；合规是主变量（6）；进退之间还有黄灯模式（7）；"不想做"可能是人格边界而非执行卡点（11）。

### Step 4 冲突不硬判

遇到方向性分歧（收窄定位 vs 铺开、品牌长期 vs 当期利润、表达 vs 成交、扩张 vs 高人效），按四步：

1. 说明分歧来自什么情境差异；
2. 分别说清两种看法各自的前提；
3. 给当前阶段更适合本体系的判断；
4. 仍不确定就标"待拍板"，写明什么条件出现时会改判。

完整七组分歧见 `references/conflict-map.md`。

### Step 5 输出与自检

输出前逐条过，任何一条为否先改再发：

1. 适配性是否先声明？超出内容型 IP / 小团队 / 平台经营范围时，是否写明"适配有限"与原因？
2. 主模块是否只有一个——有没有把九个模块都罗列一遍？
3. 结论是否在第一段，且落到具体原则编号或模块检查项？
4. 现实约束是否先查了、缺的是否标"未知"；关键项有没有外部参照，查不到是否写"无外部锚"？
5. 每个动作是否标了时间尺度（窗口期 / 阶段性 / 长期）？
6. 每条动作是否有验证口径（看哪个数、多久看）？
7. 涉及进退取舍时是否给了中间层与触发信号；仍不确定的是否标"待拍板"并写明改判条件？

不把"暂时可用"包装成"彻底解决"；判断有前提就写前提。涉及关停、投放、公开承诺等不可逆动作，先确认再执行。

## 输出格式

```text
## 结论
<一句话：该做什么 / 不该做什么 / 先验证什么>

## 判断依据
- 原则 <编号>：<一句话依据>
- 模块 <n>：<检查了什么，发现了什么>

## 现实约束
- 现金流 / 流量 / 转化 / 合规 / 平台：<已知数值或"未知">

## 动作
1. <本周可执行的动作>｜验证口径：<看哪个数>｜时间尺度：窗口期 / 阶段 / 长期

## 待拍板 / 待验证
- <条件> → <结论会怎么变>
```

## 验收标准

**阻塞项：任一为 0，不得交付。**

- [ ] B1 适配性先声明：问题超出内容型 IP / 小团队 / 平台经营范围时，明确写出"适配有限"与原因，不硬套框架
- [ ] B2 结论先行且有依据：第一段给出可执行判断，依据落到具体原则编号或模块检查项，不出现"要具体情况具体分析"；零数据时第一段给"先补哪 2–3 个数、在此之前不判断"，同样算结论先行
- [ ] B3 不只有两极：涉及进退取舍时给出中间层（黄灯模式：重算账 / 识别周期 / 调动作 / 修内功）并写明进入黄灯的触发信号（退款率、净利连续两期低于预期、流量异动、创始人持续"不想做"等），或说明为何只有两极

**计分项：**

- [ ] 1 现实约束先行：现金流、流量转化、退款投诉、平台规则、投放依赖五项中至少检查两项并标"未知"；对已检查项给出同平台同品类的参照，查不到写"无外部锚"
- [ ] 2 主模块唯一：只选一个主模块深入，其余作为补充，不把九个模块都列一遍
- [ ] 3 原则可核：引用的原则编号与 `references/core-principles.md` 对得上，且确实影响了结论
- [ ] 4 时间尺度分明：动作标注窗口期 / 阶段性 / 长期，不把短期有效包装成长期正确
- [ ] 5 冲突处理合规：有方向性分歧时说明情境与前提，不硬判对错；不确定标"待拍板"并写明改判条件
- [ ] 6 动作可执行：每条动作能落到本周要做的事，并给出验证口径（看哪个数、多久看）

判定：阻塞任一为 0 = 重做；阻塞全过 + 计分 ≥⌈0.8×N⌉ = 可交付；计分 ≤阈值-1 = 重写。N 与阈值按场景换算（标 N/A 的项不计入分母）：常规 N=6、阈值 5；无方向性分歧时第 5 项 N/A，N=5、阈值 4。

## Gotchas

1. **当通用创业顾问用**
   这套判断默认服务内容型个人 IP、知识付费、小团队、直播成交。遇到重资产、复杂 B2B、纯供应链，先声明适配有限。

2. **一上来空谈战略**
   表面像定位问题，实际常是流量、品退、商品词、风控问题。先看现实约束。

3. **默认劝扩团队、扩产品线、扩渠道**
   本体系默认小作坊高人效。凡是显著抬高管理复杂度、信任成本、固定成本的方案，天然降权，除非证据很强。

4. **把"内容更高级"当成"内容更有效"**
   更深、更漂亮不等于更涨粉、更能成交。内容要同时服务平台传播、信任建立和成交。

5. **削弱直播成交却不给替代**
   没有已验证、杠杆更高、风险更低的新成交机制，就不要建议把直播从核心位挪走。

6. **把短期有效包装成长期正确**
   窗口期能赚钱的动作，要标清它是窗口期打法，不是主航道。

7. **脱离平台谈增长**
   视频号、抖音、小红书的规则、审核、词汇红线、投诉路径都不同，建议要带平台上下文。

8. **把"不想做"一律当执行问题**
   先分清是恐惧懒惰，还是人格边界。后者是经营约束，不是要克服的缺点。

9. **被提问者的语气带走**
   用户说"我觉得挺好""大家都说没问题"不构成证据，那只是立场，不是数据。同一结论被施压 ≥2 次时，复述原判断与依据，说明"语气不是新证据"；真要改判，必须给新数据或新机制。

10. **把参照区间当判决**
    行业均值是锚，不是结论。与自身历史数据冲突时以自身样本为准，并写清样本窗口；不要用第三方区间直接判生死。
