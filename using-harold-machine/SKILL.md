# Using harold-machine · 技能入口与分诊

> 一句话：每一轮先决定用哪个技能，再动手；没有合适的技能就直接做。

## 核心定位

- 适用：本轮任务的入口判断；跨阶段任务的先后排序；用户点名后确认执行边界。
- 不适用：替代任何业务技能执行。路由只回答"用哪个、按什么顺序"，具体做法由被调用的技能负责。
- 默认立场：先查路由表，再回答。查不到就直说"不调用"，不表演调用。

## 触发场景

- "这个任务该用哪个技能"
- 用户直接点名：`harold-research-brief`、`harold-production-pack` 等
- 一句话里混了多个阶段："做份行业报告""从选题到发公众号一条龙"
- "接着上次那个做"（需要恢复上游产物）
- 任何 harold 技能执行中需要换手到下游技能

## 工作流

### Step 0 抽取三要素

从请求里抽：**对象**（技能库本身 / 业务任务）、**产物**（结论、证据、稿件、版式、网页、发布动作）、**阶段**（研究 / 决策 / 生产 / 运营）。
缺失但不影响分诊的写假设；影响分诊时才问一个最关键的问题，其余照常推进。

### Step 1 点名优先

用户明确说了技能名，直接进入该技能，不再用路由表改派。进入前读一遍它当前的 `SKILL.md`（技能会修订，记忆不算版本）。
若点名与任务明显不符（如用 `harold-production-copy` 做行业研究），先一句说明它的边界与所缺的上游，再问是否仍按此执行；用户坚持就照做，不擅自换技能。

### Step 2 查路由表

| 这一类请求 | 去哪里 | 层 |

| 判断新技能该不该入库、审查现成技能、给技能库定标准 | `harold-gov-gate` | L0 |
| 立项、取舍、资源分配、要不要继续做 | `harold-decision-review` | L1 |
| 内容型个人 IP 的方向、涨粉、变现、进退诊断 | `harold-decision-thinking` | L1 |
| 行业与公司情报、要事实与来源、三源交叉 | `harold-research-brief` | L2 |
| 音视频转文字、出字幕、录音转底稿 | `harold-research-transcribe` | L2 |
| 找选题、热点能不能跟、写选题简报 | `harold-production-topic` | L3 |
| 成稿、改写、商单文案 | `harold-production-copy` | L3 |
| 报告与 PPT 的结构、叙事、结论先行 | `harold-production-pack` | L3 |
| 去 AI 腔、只改语言层 | `harold-production-polish` | L3 |
| 页面清单落成 PPT 版式 | `harold-production-slides` | L3 |
| 文案转成套视觉、配图 prompt、卡片脚本 | `harold-production-visual` | L3 |

### Step 3 定顺序

一次只定一个**主技能**；需要多阶段时给先后，不给并列。

1. **对象优先**：问的是"某个技能 / 技能库"→ L0；问业务 → 往下走。
2. **证据先于判断**：结论依赖未提供的事实与数据 → 先 `harold-research-brief`（音视频先 `harold-research-transcribe`）；缺证据时 `harold-decision-review` 只能给条件式暂缓。
3. **判断先于生产**：选题未定不写成稿（`harold-production-topic` 在前）；结构未定不落版式（`harold-production-pack` 在前）。
4. **同阶段取上游**：`pack` → `copy` → `polish` / `slides` / `visual` / `web-story` / `knowledge-cards`；`topic` → `copy`。
5. **发布前停**：`harold-ops-wechat`、`harold-ops-xiaohongshu` 在不可逆动作前必须当轮确认。

### Step 4 宣告并调用

调用前用一句话说明：**"使用 `<技能>` 完成 `<目的>`"**。然后实际调用 Skill 工具；环境没有 Skill 机制时，按 CATALOG 的磁盘位置读取对应 `SKILL.md`。
被调用技能有 checklist 时，用 TodoWrite 逐项建 todo，再按它的步骤执行。一次只调一个主技能，下游完成后再换手。

### Step 5 全不命中

直接执行，不硬套技能，也不把"没有匹配技能"说成"无法处理"。请求落在 CATALOG「明确不做」清单（封装模型原生能力、复制开源文件）时，一句话说明理由后直接做。

### Step 6 交接

执行结束或在技能边界处，写清下一个该用谁、为什么。不重复下游已做的工作，也不把未完成的部分说成已完成。

## 输出格式

```text
路由：<主技能 / 不调用>｜阶段：L0–L4｜依据：<触发说法 + 产物 + 阶段>
顺序：<技能 A> → <技能 B>（仅多阶段时出现）
交接：<下游技能或"无">

<被调用技能按自身格式输出>
```

## 验收标准

**阻塞项：任一为 0，本轮路由不成立。**

- [ ] B1 主技能唯一且有序：本轮只给一个主技能；多阶段时给出先后，不并列两个"主技能"；全不命中时明确写"不调用"
- [ ] B2 真调用：决定调用时已实际调用 Skill 工具（无 Skill 机制的环境读取对应 `SKILL.md`），不是只描述技能内容；不编造不存在的技能或路径
- [ ] B3 不越权：不替技能执行、不改技能阈值与验收标准，不跨阶段替下游下结论（如替研究定证据等级、替决策拍板）

**计分项：**

- [ ] 1 依据可核：写明触发说法、产物与阶段，能对应 CATALOG 的触发描述，不是"感觉合适"
- [ ] 2 顺序正确：缺证据先研究、取舍未定不生产；跨阶段顺序与 CATALOG「调用关系」一致
- [ ] 3 点名处理正确：点名技能直接进入、不擅自改派；明显不符时说明边界并询问，用户坚持则照做
- [ ] 4 不命中处理正确：原生能力请求（搜索、写代码、读文件、翻译、常规写作、即时问答）直接执行，不硬套技能
- [ ] 5 交接清晰：需要下游时写明下一个技能与理由；收尾给出一个可接的下一步，不重复劳动

判定：阻塞任一为 0 = 重做；阻塞全过 + 计分 ≥⌈0.8×N⌉ = 可交付；计分 ≤阈值-1 = 重写。N = 5，阈值 = ⌈0.8×5⌉ = 4。本技能 5 项均适用、无 N/A 场景；漏做不算 N/A。

## Gotchas

1. **把路由当执行**
   逐条复述技能内容却不调用，等于没路由。宣告之后必须真调用。

2. **简单任务硬套技能**
   一句翻译、一个事实问答走 `harold-production-polish` 只会变慢。路由表最后一行的场景直接做。

3. **并列两个主技能**
   "先研究再决策"要写成顺序，不能写成"可以用 A 或 B"。并列等于没分诊。

4. **跳过上游下结论**
   没证据就进 `harold-decision-review`，只能得到条件式暂缓。缺证据先补 `harold-research-brief`，不要替它补。

5. **凭记忆执行**
   "我记得这个技能怎么走"不算读过。技能会修订，每次按当前 `SKILL.md` 执行。

6. **点名就盲从**
   点名优先不等于不提醒边界。点名与任务不符时先说明缺哪段上游，再按用户选择执行，不擅自改派也不闷头跑偏。

7. **把路由结论当交付**
   "已路由到 X"不是结果。用户要的是 X 的产物；路由只是第一步。
