# Ops Loop · 周报与闭环

> 一句话：周报不是流水账，是决定、阻塞和下一步的清单。

## 核心定位

- 适用：周报 / 月报、项目复盘、待办清理、阶段小结。
- 不适用：绩效评估、财务核算、正式对外汇报（用 `harold-production-pack`）。
- 默认交付：一页能读完，风险在最前面。

## 触发场景

- "帮我写周报"
- "这周干了啥，帮我整理一下"
- "做个项目复盘"
- "帮我把待办理一下"
- "写个月报 / 阶段小结"

## 工作流

### Step 0 收集

四类原料：本周产出（可验证）、做出的决定、阻塞与依赖、下周关键事项。
先让用户倒完，再只对「只有动作没有结果」的条目追问一句「结果是什么」，其余不追问。
用户没提到的类别不等于没有：风险与阻塞至少确认一句；确认过才写「无」，没问到的写「未提供，待确认」。

### Step 1 结构化

固定结构：需要关注 + 完成 / 进行中 / 阻塞 / 决定 / 下一周期 + 复盘一条，与输出格式一致；标题写明周期起止日期。
任一节没有内容时不留空白：确认过写「无」，未收集到写「未提供，待确认」，等待外部答复写「待定（缺 X）」。
周期不是周时（月报 / 阶段小结），标题写「月报」，并把「本周」换成「本月」、把「下周」换成「下月」，结构与判据不变。

### Step 2 未完项过三关

进行中 / 下一周期 / 阻塞未解除 / 顺延项，逐条过三关：有结果吗？有下一步吗？有负责人和日期吗？三关不过的，当场改写。
进度不凭感觉估：写「已完成 n / 总 m」或阶段（如「接口联调中」）；给不出口径就不写百分数。
完成项不要求下一步，只核结果是否可复核。
负责人 / 日期未知时写「待定（缺 X）」，不得编造人名或日期。

### Step 3 风险前置

阻塞与依赖放在最前，不要埋在中段。第 0 节只放跨项目风险与需要上级决策的事；本项目内、有明确等待对象的卡点放第 3 节。依赖对象不明时留在第 3 节并标「待定（缺依赖方）」，不上升为第 0 节。确认无风险时第 0 节写「无」；未收集到写「未提供，待确认」，不得把未知写成「无」。

### Step 4 一条复盘

本周期一个可复用教训：现象 → 原因 → 下次怎么做。
只写一条，写多了等于没写。

### Step 5 回写

回写到用户指定的任务系统（Jira / 飞书任务 / 表格等）；未指定时输出「状态变更清单」供用户粘贴，不擅自改外部系统。
未完成项顺延须写明原因，不静默滚动。

## 输出格式

```text
# 周报 / 月报：<周期，含起止日期>

## 0. 需要关注
- <跨项目风险 / 需上级决策>｜依赖：<谁>｜影响：<什么>

## 1. 完成
- <结果>（可验证口径）

## 2. 进行中
- <事项>｜进度：<已完成 n / 总 m，或阶段>｜下一步：<动作>｜负责人｜日期

## 3. 阻塞
- <卡点>｜等待：<谁 / 什么>｜预计解除：

## 4. 决定
- <决定>｜依据｜影响范围｜决定人｜生效时点

## 5. 下周期（周报即下周，月报即下月）
- <事项>｜负责人｜日期

## 6. 复盘一条
现象 → 原因 → 下次怎么做
```

## 验收标准

**阻塞项：任一为 0，不得发出，不看计分项。**

- [ ] B1 不编造：完成项是结果不是动作（"已发请求"不等于"已对接"），且能被第三方复核（数量 / 链接 / 交付物）；未知的人 / 日期 / 进度写「待定（缺 X）」
- [ ] B2 结构完整：标题含周期起止日期；需要关注置顶 + 完成 / 进行中 / 阻塞 / 决定 / 下周期（周报即下周，月报即下月）+ 复盘一条
- [ ] B3 不隐瞒风险：跨项目风险与需上级决策的事必须置顶，写明等待谁 / 什么与预计解除；本项目内有明确等待对象的卡点放第 3 节并写明等待对象，不得省略或降级为「进行中」；未收集到风险时写「未提供，待确认」，不得写「无」

**计分项：**

- [ ] 1 未完项有三要素（下一步 / 负责人 / 日期；未知写「待定（缺 X）」）
- [ ] 2 决定有依据、影响、决定人与生效时点（依据不明写「依据待补」，决定人未知写「待定（缺决定人）」）
- [ ] 3 复盘可执行（现象 → 原因 → 下次怎么做，能落到具体动作）
- [ ] 4 无未解释顺延
- [ ] 5 风险分流正确：第 0 节只放跨项目风险与需上级决策的事；本项目内有明确等待对象的卡点放第 3 节；依赖方不明留第 3 节并标「待定（缺依赖方）」
- [ ] 6 空节有状态：确认无写「无」，未收集写「未提供，待确认」，外部待答复写「待定（缺 X）」；不留空白

判定：阻塞任一为 0 = 重做；阻塞全过 + 计分 ≥⌈0.8×N⌉ = 可交付；计分 ≤阈值-1 = 重写。N 与阈值按场景换算（标 N/A 的项不计入分母）：常规 6/5；无决定（第 2 项）5/4；无未完项（第 1、4 项）4/4；无风险（第 5 项）5/4；无空节（第 6 项）5/4；多项同时不具备时按剩余项数重算，第 3 项复盘不设 N/A。N/A 仅限材料本身不具备该情形，漏做不算 N/A；用户豁免某项时仍计入分母，自检记为未做。

## Gotchas

1. **流水账**
   "开了三个会、看了两份报告"没有信息。写成产出与决定。

2. **计划写成完成**
   "已对接"实际是"已发出请求"。用完成时态前先确认结果。

3. **只报进展不报风险**
   周报的价值在暴露阻塞；不写风险等于隐藏问题。

4. **"持续推进"占位**
   没有下一步的进行中事项，要么拆动作，要么移出。

5. **复盘变成表扬或自责**
   复盘只回答一个问题：下次哪一步可以改。

6. **写给上级的表演**
   周报首先是给自己的账本；先能自用，再谈好看。

7. **把「没收集到」写成「无」**
   "无风险"是结论，"没问过"是空白。没确认过就写「未提供，待确认」。

8. **进度百分比拍脑袋**
   "完成 70%"说不清算了多少项。改成「已完成 n / 总 m」或具体阶段。

9. **周报没有起止日期**
   "本周周报"十个人十种理解。标题写清周期起止，否则完成项无法对账。
