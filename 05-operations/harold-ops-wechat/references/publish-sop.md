# 发布 SOP（长文与贴图）

本文件是 `harold-ops-wechat` 的细则来源。SKILL.md 只做总控，具体口径以这里为准。

## 1. 形态选择

| 选题类型 | 贴图 | 长文 |
|---|---|---|
| 一图能说完的金句、清单、数据榜 | 是 | 否 |
| 需要多张图层层展开的科普 / 复盘 / 方法论 | 是 | 否 |
| 靠故事 + 论证 + 反转推进的 3000 字以上深度稿 | 否 | 是 |
| 人物特稿、历史复盘 | 否 | 是 |
| 热点速评、节日借势、工具盘点 | 是 | 否 |
| 核心判断需要卡片化的商业 / 投资洞察 | 是 | 否 |

按正文字数分档（与 SKILL.md Step 0 一致）：

| 分档 | 字数 | 处理方式 |
|---|---|---|
| 贴图 / 长图 | ≤1000 字 | 3:4 竖图，标题 ≤20 字 |
| 短长文 | 1000–3000 字 | 不拆篇，正常图文排版；头图 2.35:1，正文图 16:9 |
| 长文 | >3000 字 | 按第 2 节长文 SOP 处理，必要时拆篇 |

惯例配比：长文一周 1–2 篇立专业定位，贴图日更 1–2 条保活跃度。用户没指定时按其更新节奏给建议，不替用户定。

## 2. 长文 SOP

### 2.1 Markdown 结构

```markdown
---
title: 文章标题
author: 作者名
---

# 标题

正文段落……

![头图描述](./assets/01-cover.png)

## 小标题

正文段落……
```

要求：

- 一个 H1；正文用 H2，不跳级。
- 图片引用路径必须真实存在，文件名用 ASCII，避免中文路径在转换时报编码错。
- 正文不留 `**加粗**`、`#`、`---` 等原始标记，格式由渲染这一步完成。

### 2.2 排版规则

1. 段落每段 3–5 行，长段拆开；重要数据单独成段并加粗。
2. 金句单独成段，一段一句，不加引号也可以。
3. 配图节点固定：头图（标题下）→ 冲突后 → 论证中段 → 高潮后 → 收尾前（可选）。
4. 代码块前后留白，技术类文章保留语法高亮。
5. 全文只用一个主题，不混排。

### 2.3 主题

| 主题 | 风格 | 适用 |
|---|---|---|
| default | 标准排版 | 默认主题 |
| grace | 优雅简约 | 深度分析、商业洞察（需用户指定） |
| simple | 极简 | 技术教程、工具测评（需用户指定） |

默认主题 `default`，用户指定时以其为准。

### 2.4 自动排版（可选，自行安装）

本技能不捆绑排版引擎，也不分发第三方代码。需要自动把 Markdown 转成公众号内联样式 HTML 时，可自行安装开源项目 **doocs/md**：

- 来源：https://github.com/doocs/md
- 许可：WTFPL（Do What The Fuck You Want To Public License）
- 用法：按其 README 本地部署或用在线版，粘贴 Markdown、选主题、复制渲染结果到公众号编辑器。

使用前自行确认版本与许可条款；本技能只提供流程与验收口径，不提供该项目的代码、镜像或补丁。

### 2.5 手工排版兜底

没有引擎时，按以下顺序手工处理：

1. 正文用编辑器默认字体，字号 15–16px，行距 1.7–1.8，段间距 1em。
2. 小标题加粗、字号 +2，颜色用深色不用纯黑，段前留白大于段后。
3. 引用块用左侧竖线 + 浅灰底；列表用圆点，不用数字序号堆叠。
4. 强调只加粗关键词，不加下划线、不用彩色字。
5. 成品在浏览器预览里过一遍引用块、列表、图片三处，再复制进后台。

### 2.6 图片替换

1. 渲染时图片位置标成 `[[IMAGE_PLACEHOLDER_N]]`。
2. 粘贴 HTML 后逐个定位占位符，删掉占位文本，再粘贴已上传的图片。
3. 替换顺序与正文出现顺序一致，替换完数一遍张数。
4. 微信编辑器里补传的图，发布前在手机预览里再确认一次。

## 3. 贴图 SOP

### 3.1 硬约束

| 字段 | 上限 | 备注 |
|---|---|---|
| 标题 | 20 字 | 超长会被截断 |
| 正文 | ≤ 1000 字 | 必须已自然分段，可直接粘贴 |
| 摘要 | 120 字 | 必须人工拟定；不填会默认抓正文前 54 字，不可控；超长会报错 |
| 图片张数 | 按内容深度定 | 10、12、15 张都可以，不机械固定 |
| 单图比例 | 3:4 竖图 | 朋友圈完整呈现 |
| 单图字数 | 50–150 字 | 一张图讲完一个模块，不是金句摘要 |
| 颜色数 | ≤ 3 种 | 一篇内色系统一 |

### 3.2 流程

1. 读原文，先定一句话主旨和卡片张数。
2. 写卡片脚本和贴图正文初稿；正文像人说话，不写"第一点/第二点"提纲腔。
3. 封面单独设计：背景用生图只出无文字主视觉，标题和中文文案用 HTML/CSS 叠字；先出 `cover-for-review.png` 给用户审核。
4. 审核通过后渲染全组卡片到 `assets/01-cover.png … NN-*.png`。
5. 清理 `assets/`：只留最终上传图，删掉 `.DS_Store`、背景图、审核图、旧图。
6. 逐项过交付检查单，全部通过才算 READY。
7. 交付 `01-tietu-post.md` + `assets/`，由人手动上传发布。

### 3.3 卡片节奏（每张一个完整模块）

| 卡 | 角色 | 任务 | 字数 |
|---|---|---|---|
| 01 | 封面 | 反常识断言 + 一句核心论点 | 30–60 |
| 02 | 背景 | 起因、当事人、时间地点 | 80–120 |
| 03 | 数据 | 3–5 个数字，每个一句解读 | 100–150 |
| 04 | 类比 | 历史镜像或核心比喻 + 落点 | 100–150 |
| 05 | 反差 | 双标 / 新旧 / 认知落差 | 80–120 |
| 06 | 引言 | 名人原话 + 出处 + 解读 | 60–100 |
| 07 | 论点 | 全文最 sharp 的判断 + 论据 | 100–150 |
| 08 | 收束 | 总结 + 下篇预告 + 关注引导 | 60–100 |

张数按内容深度增减，节奏顺序可调，但封面必须第一张。

### 3.4 正文写法

- 开头：承认复杂性或抛悬念，让人愿意往下刷。
- 中段：把事实、数字和真正的问题摊开。
- 转折：说明这不是简单站队，而是利益 / 风险 / 人性的问题。
- 收束：一句有余味的落点，引读者看图。

禁止：一整坨不分段；机械提纲腔；"首先 / 其次 / 最后"式套话；把长文整段抄进图里。

### 3.5 命名与目录

```text
outputs/YYYY-MM-DD_主题/
├── 01-tietu-post.md
├── design-sources/
│   └── cover-for-review.png
└── assets/
    ├── 01-cover.png
    ├── 02-anchor.png
    ├── 03-main-1.png
    ├── 04-twist.png
    └── NN-cta.png
```

文件名前缀从 `01-` 连续编号，按可见阅读顺序排；不要为了迁就编辑器而把封面改成最后一张。

## 4. 发布前检查单

### 4.1 通用

> 〔自检〕由本技能给结论；〔人工〕AI 看不到后台，列入交付物的「待人工确认」，不代勾。

- [ ]〔人工〕账号正确（多账号时截图确认）
- [ ]〔自检〕标题 ≤20 字，人工拟，未被自动压缩；20–30 字另给 ≤20 字卡片短版；超 30 字在摘要给短版
- [ ]〔自检〕摘要 ≤ 120 字，人工拟定，带悬念
- [ ]〔人工〕原创声明按需勾选
- [ ]〔人工〕作者署名正确
- [ ]〔自检〕预览无异常：引用块、加粗、列表、代码块
- [ ]〔人工〕手机预览通过（图不裂、正文不截断）
- [ ]〔人工〕可见范围确认（群发 / 仅自己 / 定时）
- [ ]〔自检〕广告标识：商业推广 / 带货内容已显著标「广告」
- [ ]〔自检〕绝对化用语：无「最佳 / 第一 / 国家级 / 独家」等禁用表述
- [ ]〔自检〕诱导分享：无「分享得 X / 集赞 / 转发解锁」
- [ ]〔自检〕版权来源：图片、字体、音乐来源可商用或已获授权
- [ ]〔人工〕转载与肖像授权：转载已获授权，含可识别人脸已取得同意
- [ ]〔人工〕敏感行业资质：医疗 / 金融 / 教育等按需提供资质
- [ ]〔自检〕排版稿已实际粘进公众号编辑器或草稿箱试过一次，引用块 / 加粗 / 列表未被剥掉

合规六项不涉及的写「不适用，原因 X」，不能留空；任一项判定为「不合规」时，改稿后再重过本单，不带着问题进入发布。

### 4.2 长文 / 短长文另加

- [ ]〔自检〕头图文件 2.35:1；〔人工〕后台已设为封面
- [ ]〔自检〕头图主体、人脸、标题在中间约 1:1 安全区内（列表 / 分享预览会把两侧裁掉）
- [ ]〔自检〕正文图张数符合形态：长文 3–4 张，短长文 2–3 张，位置正确
- [ ]〔人工〕全部图片上传成功
- [ ]〔自检〕公式已转图，脚注已改成文末编号列表
- [ ]〔自检〕文末无残留占位符 `[[IMAGE_PLACEHOLDER_N]]`

### 4.3 贴图另加

- [ ]〔人工〕封面单独设计并经用户审核
- [ ]〔自检〕只有封面背景用生图；正文卡片为 HTML/CSS 渲染
- [ ]〔自检〕`assets/` 只留最终上传图，顺序从 `01-cover.png` 开始
- [ ]〔自检〕图片全为 3:4，无拉伸、无裁切
- [ ]〔自检〕正文字数 ≤ 1000 且已分段

## 5. 发布与核验

1. 默认人工发布：交付排版稿与素材包，说明上传顺序与粘贴位置。
2. 用户确认发布后，先存草稿，再预览，再点发表。
3. 发表后回后台核对：图片张数与顺序、正文完整性、封面缩略图、标题未截断。
4. 记录发布信息（标题、时间、形态、素材目录），便于复盘时对照。

## 6. 失败回滚

| 失败 | 判断依据 | 处置 |
|---|---|---|
| 样式丢失 | 粘贴后引用块、列表变成纯文本 | 从排版稿复制富文本重贴；检查是否复制了源码 |
| 图片裂图 | 预览出现破图或空白 | 重新上传素材库，换地址；确认为 3:4 / 16:9 原比例 |
| 公式原样显示 | 正文出现 `$$` 或 `\(` | 公式转 PNG 重插，全篇排查同类 |
| 脚注丢失 | 编号在、文末注释没了 | 改为文末手工编号列表，正文用上标数字 |
| 标题被截断 | 后台标题与拟定不一致 | 人工重拟更短的标题，不沿用压缩结果 |
| 草稿内容回退 | 保存后 reopen 变旧内容 | 关闭手机端助手，电脑端重存一次并复核 |
| 已群发且有错 | 推送已到达 | 错在可改范围内先改：标题 3 字内、正文 120 字内、图片 3 张内，封面与摘要可改；超出可改范围或错在核心结论再删除止损；不追加群发解释，改在其他渠道说明 |

回滚原则：一次只改一个变量，改完立刻预览；同一路径连续失败两次，停下来换方案，不硬试。

## 7. 自动化发布（可选备用）

默认不启用。仅在用户明确要求自动化，且完成不可逆确认后，才考虑以下路径：

1. **半自动**：脚本只负责填标题、正文、上传图片到草稿，最后一步由人点发表。
2. **全自动**：需要浏览器登录态、稳定的编辑器选择器、可回滚的草稿。任一条不满足就退回半自动。
3. **不建议**：直接调后台内部接口写草稿。字段多、易变、失败时容易写出半截内容。

执行前确认：账号、标题、可见范围、发布时间、是否已有同名草稿会被覆盖。

已知限制（选择方案前先告知用户）：

- 编辑器富文本区域对模拟输入敏感，可能触发页面跳转，正文丢失。
- 手机端助手会与电脑端抢同一草稿，出现内容回退。
- 封面图上传按钮通常无法脚本化，需人工补。
- 草稿保存返回成功，不代表图片真的上传成功，必须人眼核验。

本技能不附带任何发布脚本。需要时自行搭建，并把每一步的失败判定写进自己的流程。
