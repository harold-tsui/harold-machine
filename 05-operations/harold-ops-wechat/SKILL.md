# Ops WeChat · 公众号成稿到发布

> 一句话：写作不归这里管；这里只保证成稿排得干净、图不缺、发之前查过。

## 核心定位

- 接手点：已有成稿（Markdown 或纯文本），或用户明确要把某篇稿子发到公众号。
- 交付点：可粘贴的排版稿 + 配图/贴图素材包 + 发布前检查单；默认由人点发布。
- 不适用：选题、叙事结构、文案打磨、标题策略 → `harold-production-pack`（成稿）、`harold-production-polish`（润色）。
- 不适用：小红书 / 头条等其他平台；视频脚本。
- 一句话边界：本技能只管「成稿 → 发布」这一段，往上游一步都不走。

## 触发场景

- "把这篇发公众号"
- "帮我排版，贴到公众号后台"
- "做成贴图（图文卡片）发出去"
- "公众号预览样式乱了 / 图片裂了，帮我看看"
- "这篇要发，先帮我检查一遍"

## 工作流

### Step 0 判定形态

先按正文字数分档，再动手。判据见 `references/publish-sop.md` 的形态选择表。

| 分档 | 字数 | 处理方式 |
|---|---|---|
| 贴图 / 长图 | ≤ 1000 字 | 3:4 竖图，标题 ≤ 20 字，正文 ≤ 1000 字 |
| 短长文 | 1000–3000 字 | 不拆篇，正常图文排版；头图 2.35:1，正文图 16:9 |
| 长文 | > 3000 字 | 按 `references/publish-sop.md` 长文 SOP 处理，必要时拆篇 |

形态不明确就问一句，不要两边都做。

### Step 1 成稿结构对齐

- frontmatter 只留 `title` / `author`。
- 标题层级：一个 H1，正文用 H2，不跳级、不用 H3 凑层级。
- 图片引用写成 `![描述](./assets/01-cover.png)`，路径相对素材包根目录，并确认文件真实存在。
- 段落每段 3–5 行；金句、关键数据单独成段。

### Step 2 排版

- 主题：默认 `default`，用户指定时以其为准。
- 正文不留原始 Markdown 标记（`**加粗**`、`#`、`---`），全部转成内联样式，格式只在这一步处理。
- 转换后逐项看：引用块、加粗、列表、代码块是否都成了内联样式。
- 图片走占位符，粘贴后按顺序替换；不要指望外链图在编辑器里直接显示。
- 没有排版引擎时，按 `references/publish-sop.md` 的手工规则做，不要临时拼一堆 class。

### Step 3 配图

- 长文 / 短长文：头图 1 张（2.35:1，1504×640）+ 正文图（16:9，1344×756），插在冲突后、论证中段、高潮后；长文 3–4 张，短长文 2–3 张。
- 贴图：3:4 竖图（1080×1440），张数按内容深度定；封面取素材包内第一张（`01-cover.png`）。
- 封面背景只生成无文字图，中文标题用 HTML/CSS 本地叠字，避免生图错字。
- 一篇文章只用一套视觉风格；模板与提示词见 `references/visual-style.md`。

### Step 4 发布前检查

逐条过 `references/publish-sop.md` 的检查单：标〔自检〕的项由本技能给结论，标〔人工〕的项（账号、原创声明、作者署名、后台预览、可见范围等）列入「待人工确认」，不代勾。有未过项，不进入发布。

合规六项必须先有结论：商业推广是否显著标「广告」、有无绝对化用语（最佳 / 第一 / 国家级 / 独家）、有无诱导分享（分享得 X / 集赞 / 转发解锁）、图片 / 字体 / 音乐的版权来源、转载与肖像授权、敏感行业资质；不涉及的写「不适用，原因 X」，不能留空。

排版稿要实际粘进公众号编辑器或草稿箱试一次，确认引用块、加粗、列表没有被剥掉；只看浏览器预览不算过。

### Step 5 发布（默认人工）

默认路径：把素材包交给用户，由人在公众号后台粘贴、上传、预览、发表。
默认不代点「发表」，也不代点「群发通知」；只有走自动发布分支（B1 四要素齐全 + 当轮确认）时才由 AI 执行最后一步，否则停在交付素材包。

素材包必须包含：

1. 成稿 Markdown（含标题）
2. 配图文件（命名 `01-cover.png` 起，按阅读顺序连续）
3. 手动发布步骤清单（上传顺序、粘贴位置、预览与发表动作）
4. 检查单结果（逐项勾选，未过项写处理方式）

### Step 6 发布后核验与回滚

- 回后台看真实状态：图缺没缺、正文有没有被截断、封面是不是第一张。
- 出问题按下表处理，不猜测、不反复重试同一条路。

| 症状 | 处理 |
|---|---|
| 样式丢失 | 回到排版稿复制富文本，不要复制源码；必要时重贴并逐段检查 |
| 图片裂图 | 重新上传到素材库，正文引用换成上传后的地址，再预览 |
| 标题被截断 | 人工重拟更短的标题，不用自动压缩结果 |
| 已群发且内容有错 | 错在可改范围内先用后台「修改」：标题 3 字内、正文 120 字内、图片 3 张内，封面与摘要可改；超出范围或错在核心结论才删除止损，推送已到达读者；另行说明，不做二次群发补救 |

## 输出格式

```text
# 公众号交付：<标题>

## 1. 形态
贴图 / 短长文 / 长文｜理由：<一句>

## 2. 排版稿与素材包
- 排版稿：<路径 或 内联>
- 素材包目录：<路径 或「未生成，原因 X」>
- 成稿：<标题>.md（含标题）
- 主题：<default；用户指定时写指定值>
- 标题：<正文标题>｜卡片短版：<≤20 字；贴图必填，图文 20–30 字时必填，≤20 字写「同正文」>｜摘要：<≤120 字，人工拟定>

## 3. 图片
| 序号 | 文件 | 用途 | 比例 | 状态 |
|---|---|---|---|---|
| 01 | 01-cover.png | 封面 | 3:4 / 2.35:1 | 已就位 |

## 4. 发布前检查
- [x] <已过项>
- [ ] <未过项>｜原因｜处理

## 5. 发布方式
人工发布（默认）｜自动发布（已确认：账号 / 标题 / 可见范围 / 时间）

## 6. 待人工确认
- <只能人来判断的项>
```

素材包未生成时，「素材包目录」不得留空，必须写「未生成，原因 X」。

## 验收标准

**阻塞项：任一为 0，不得交付，不看计分项。**

- [ ] B1 不擅自发布：默认停在人工发布，未代点「发表 / 群发通知」；自动发布前四要素（账号 / 标题 / 可见范围 / 时间）齐全，且已拿到用户在本轮的明确确认
- [ ] B2 素材包可交接：成稿 md、配图（按阅读顺序连续命名）、手动发布步骤、检查单结果四项齐全；未生成时写「未生成，原因 X」，不留空
- [ ] B3 样式不丢：正文无原始 Markdown 标记（`**` / `#` / `---`），全部为内联样式，层级不跳级

**计分项：**

- [ ] 1 形态判定有理由，未长文贴图混做；主题按声明执行（默认 `default`，用户指定不改）
- [ ] 2 图片数量、比例、插入位置符合形态规格，引用的文件真实存在；配图与所在段落内容一致；头图主体与标题在中间安全区内（2.35:1 在列表 / 分享预览会被裁成约 1:1）
- [ ] 3 标题口径正确：贴图为硬限 ≤20 字；图文形态建议 ≤20 字，20–30 字可保留正文标题但另给 ≤20 字卡片短版，超 30 字在摘要给短版；摘要 ≤120 字且人工拟定
- [ ] 4 检查单逐项有结论，未过项写了处理方式；合规六项（广告标识 / 绝对化用语 / 诱导分享 / 版权来源 / 转载与肖像授权 / 行业资质）均已判定，不适用时写明原因；排版稿已实际粘进公众号编辑器或草稿箱试过一次
- [ ] 5 公式与脚注可用：正文无 `$$` / `\(` 残留，公式已转图；脚注已改文末人工编号列表（全篇无公式与脚注时记 N/A，按通过计）
- [ ] 6 发布后核验：本轮执行了发布时，已回后台核验图片、正文截断、封面顺序，并按症状给出回滚处置；未进入发布阶段记 N/A，按通过计

判定：阻塞任一为 0 = 重做；阻塞全过 + 计分 ≥⌈0.8×N⌉（N 为计分项数，N/A 不计入分母；满项 N=6，阈值 5；1 项 N/A 时 N=5，阈值 4；2 项 N/A 时 N=4，阈值 4）= 可交付；计分 ≤阈值-1 = 重写。

## Gotchas

1. **样式丢失**
   从网页或预览页复制富文本，粘进公众号编辑器后 class 全被剥掉，只剩裸文字。
   微信只认内联样式；排版稿必须是内联样式，粘贴前先在预览里看一眼引用块和列表。

2. **图片裂图**
   正文引用本地路径或外链图，读者端一律裂。
   图片必须先上传到公众号素材库，正文用上传后的地址；发布前用手机预览再确认一次。

3. **公式与脚注渲染失败**
   微信不吃 KaTeX / MathML，也不认 `<sup>` 脚注样式，公式会原样显示成 `$$...$$`，脚注编号直接消失。
   公式转 PNG 插入，脚注改成文末编号列表手工写；一组里有一处，就全篇排查同类。

4. **发布后不可撤回**
   群发推送发出即到达，删除文章只是把页面下线，不能收回已送达的消息；订阅号一天只有 1 次群发，服务号每个自然月只有 4 次，删除已发文章不恢复次数。
   点「发表」前必须完成不可逆确认，见下节。

5. **标题长度**
   20 字是列表卡片 / 贴图的展示约束，不是正文标题的硬限制。
   标题建议 ≤20 字（列表卡片展示更完整）；20–30 字时正文标题可保留，卡片 / 列表另给 ≤20 字短标题；超过 30 字需在摘要里给短版。

6. **草稿被客户端覆盖**
   手机端公众号助手改动过同一条草稿，会让电脑端的更新看起来「没保存」。
   从保存到发表只在电脑端操作，中途不碰手机端；发现内容回退，重新保存一次再核验。

7. **只查样式不查合规**
   排版干净、图片齐全，但正文写着「全网第一」「转发解锁」，或配图来自搜索引擎、字体是未授权商用字体。
   群发不可撤回，违规的代价是删文、限流、封号。发布前先过合规六项，不涉及的写「不适用」，不能默认通过。

8. **头图关键信息放在两侧**
   2.35:1 头图在历史消息列表和分享预览里按中间约 1:1 裁剪，两侧会被切掉。
   标题、人脸、主体放中间安全区，左右两侧只放可裁背景。

## 不可逆动作确认规则

发布、群发、删除文章、覆盖已有草稿，都算不可逆或高代价动作。执行前必须：

1. 用一句话写清四件事：**哪个账号、什么标题、发给谁（群发 / 仅自己可见）、什么时候发**。
2. 拿到用户在**当前轮**的明确确认（"确认发布"或等价表述）。
3. 用户此前说过"帮我发"不构成对具体参数的授权；参数有任何变化，重新确认。
4. 没有登录态、账号不明、或无法预览时，降级为交付素材包，不强行自动化。
5. 确认后也先存草稿并预览，再执行最后一步。
